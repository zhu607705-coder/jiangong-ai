# 语料与训练样本整理

这条流程负责把已有公开资料整理成可检索、可标注、可追溯的材料，并在标注和用途记录满足条件后导出本地 SFT 样本。不会启动权重训练，也不会自动上传语料。

## 当前材料与用途

第一批来自项目内已经保存的 6 条公开来源：杭州真实研究记录中的 5 条来源，以及 1 份国家城市更新政策 HTML 快照。其中 5 条有正文，另 1 条只有元数据；正文 11,691 字，分为 17 个文本块及对应的 17 条待标注问答候选。来源版本及实测统计以 `data/local/corpus/latest.json` 指向的 `report.json` 为准。

| 材料 | 当前用途 | 不自动推定的用途 |
|---|---|---|
| 公开原文、来源 URL、获取时间、哈希 | 本机查阅、检索、标注候选 | 训练授权、公开再分发、现行政策适用性 |
| 10 个合成输入，包括顺序交换版本 | 同一基础案例家族下的回归检查 | 独立测试集、真实企业案例、监督训练答案 |
| 8 条已保存模型记录，包括 1 次失败 | 仅登记工件指针、状态与生成性质 | 人类金标准、真实项目决策结论 |
| 后续经核对的来源授权和人工标签 | 通过校验后导出对应 train/development 集 | 自动提升为独立最终评估集 |

既有公开材料已经参与过开发，第一批均登记为 `development`。这不是从 17 条样本中随机切出一份“测试集”。当前没有锁定审计集，也没有真实企业效果标签。采集记录没有可靠发布日期的条目保留 `null`；获取时间不替代生效时间。

## 日常操作

在项目目录运行；当前电脑先启用自带 Node：

```bash
export PATH="$PWD/.tools/node/bin:$PATH"
npm run corpus:build
npm run corpus:search -- --query "城市更新 实施组织"
```

打开 `data/local/corpus/语料台账.md` 看材料目录和待标注入口。生成文件均放在已被 Git 忽略的 `data/local/corpus/`，源码目录 `data/corpus/` 仅保存采集配置与说明。

检索复用 `services/capabilities/analysis.py` 的 BM25/RETQA 公共入口；HTML 提取复用现有 Readability。结果给出来源、原文块、Unicode 字符起止位置和快照时间。检索不调用外部模型，不把快照自动写入当前项目决策。

从工作台已经完成的真实公开研究中归集资料：

```bash
npm run corpus:collect -- --run RUN-4aa39374-6648-4922-bbc8-b494dd3a69aa
```

该命令只读取本机 4310 服务，保留公开、非合成来源，过滤内部资料。运行里的模型结论和会话推理不作为语料正文；归集不会触发新模型调用。重复执行按正文和 URL 去重，来源工件记录保留。

## 新材料入口

先通过工作台已有解析/研究能力取得正文，也可以准备一个来源包，再执行：

```bash
npm run corpus:import -- --file /完整路径/source-bundle.json
```

来源包格式如下，示意字段必须换成真实内容；不会把示意样本当作已采集材料：

```json
{
  "schema_version": "1.0",
  "family_id": "实际项目或同源文件家族的稳定标识",
  "split": "development",
  "origin": "获取方式及原始文件位置",
  "sources": [{
    "id": "该来源的稳定标识",
    "title": "原文标题",
    "url": "https://example.org/替换为真实原文地址",
    "data_class": "public",
    "visibility": "public",
    "synthetic": false,
    "retrieved_at": "2026-09-28T00:00:00Z",
    "content_status": "full_text",
    "untrusted_text": "替换为实际取得的原文"
  }]
}
```

`Source` 沿用主项目的 Canonical Schema，不新增另一套业务来源类型。`hash` 可省略；提供时必须是 `untrusted_text` 的 SHA-256，原始文件字节哈希应另留在获取凭证中。只有新的、与开发/回归材料没有同源关系的材料才应指定 `train`。同项目、同 URL 的修订、规范化重复和明显近重复会连成一组；跨组划分冲突会拒绝归集。对长篇改写、翻译稿等，必须自行填写一致的 `family_id`，字符近重复不能识别所有改写。

当前公开采集入口不接收企业原件。内部项目资料继续留在项目上传区；后续需明确脱敏范围、允许用途、对象关系和时间，再扩展对应的私有材料适配，不能为了导入而将其改标成 public。

## 标注到导出的闭环

每条 `candidates.jsonl` 都带有问题草稿、对应原文、来源链接和内容版本。`annotation-template.jsonl` 是空白草稿，`status: draft` 不会通过正式导出。

1. 对照原文修改问题，写出答案、原文中的逐字证据和仍未知的条件。政策陈述、建议、许可事实和项目约束要分开；不得只因原文谈到某能力就推定该项目具备它。
2. 从模板挑选已经核对的行，填入真实核对者、ISO 时间、答案和引用，确认脱敏检查后设 `privacy_cleared: true`、`status: approved`，保存至 `data/local/corpus/reviews.jsonl`。这是人工核对记录，不由程序自动署名。
3. 未采用的条目可以只记录 `candidate_id`、`candidate_sha256`、`status: rejected`、`reviewer_kind: human`、`reviewer`、`reviewed_at` 和 `reason`，无需编造答案。每个候选只保留一条当前标注；历史修改另行留档。
4. 对允许本地监督训练的**具体正文版本**，在 `data/local/corpus/grants.jsonl` 每行记录一条用途凭证：

```json
{"document_id":"从 documents.jsonl 复制","content_sha256":"从 documents.jsonl 复制完整哈希","allowed_use":"local_sft","evidence":"实际许可或材料所有者授权的可追溯凭证","attested_by":"实际核对者","attested_at":"真实核对时间，ISO 格式"}
```

程序检查记录的结构和版本，不替代对凭证真实性或许可范围的核对。缺少用途凭证的批准标签会留在待导出清单，不自动放行。

```bash
npm run corpus:export
```

导出先重建当前来源，拒绝过期候选哈希、伪造的原文引用、重复标注、模型冒充人工核对、未来时间、疑似凭据和跨集合的同源资料。合法结果写入 `exports/<版本>/train.jsonl`、`development.jsonl` 和 `manifest.json`；`exports/latest.json` 给出当前导出状态。校验失败会将当前导出状态设为 `blocked`，之前的版本仍保留。

每条样本的 `messages` 可用于后续 SFT 数据适配；来源、字符位置、标注和用途记录另放在 `provenance`，不进入模型的输入消息。只有 `train.jsonl` 是训练集合，`development.jsonl` 不应合并进去。没有批准训练行时导出为空，状态为 `awaiting_approved_training_rows`，不把空导出算作训练已就绪。

## 接下来的收集重点

| 优先级 | 收集对象 | 要保留的关系 | 可支持的后续任务 |
|---|---|---|---|
| 1 | 脱敏后的项目判断材料、建筑/用地/租赁清单 | 项目、建筑、资料时点、原文页/行、单位 | 证据提取、缺项识别、同对象事实对齐 |
| 1 | 企业意见与专家修改记录 | 原话、发言权限、适用项目、修改前后及理由 | 事实/约束/偏好/经验/未知分类 |
| 2 | 政策及案例原文的完整版本 | 发布、生效、废止时间，修订和转载关系 | 时点正确的检索与引用 |
| 2 | 方案比较的专家选择与反例 | 相同输入条件、选择理由、反证、未决条件 | 条件比较；有真实偏好对后再考虑偏好训练 |
| 3 | 后续决定和结果反馈 | 决策时点可见材料与事后结果分开保存 | 有效性评估，避免把未来结果泄漏到历史输入 |

先积累能串起“材料 → 判断 → 修改 → 决定”的完整案例。现阶段 17 条候选是标注流程的起点，不是足够训练行业模型的数据规模。
