# 服务器部署与访问

部署目标为 `zhuhangcheng@10.70.223.113`，Ubuntu 24.04 x86_64。应用沿用项目现有 Node host、Python 专业能力和 PGlite 数据库，前端使用生产构建。服务仅监听服务器回环地址，通过 SSH 隧道访问。

## 打开服务器工作台

在有该服务器 SSH 权限的电脑运行，并保持终端连接：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 15173:127.0.0.1:4310 zhuhangcheng@10.70.223.113
```

浏览器打开 **http://127.0.0.1:15173/**。本机研发页面 `5173` 与服务器页面 `15173` 可以同时保留。服务器 IP 根路径没有开放 HTTP 服务；访问者需要校园网或已有网络通道，以及 SSH 登录权限。

## 服务与目录

| 项目 | 路径或配置 |
|---|---|
| 部署根目录 | `/home/zhuhangcheng/apps/haizhizi` |
| 当前代码 | `current`，指向 `releases/<Git commit>` 或带部署时间后缀的版本目录 |
| Node 24 | `toolchain/node`，指向官方固定版本目录 |
| Python 环境 | `current/.venv` |
| 运行数据库、项目与材料 | `shared/data` |
| 服务端配置 | `shared/server.env`，权限 `600` |
| Node 服务 | 用户服务 `haizhizi-host.service`，`127.0.0.1:4310` |
| Python 服务 | 用户服务 `haizhizi-capabilities.service`，`127.0.0.1:4311` |
| 服务配置文件 | `~/.config/systemd/user/haizhizi-*.service` |

两个服务共享随机生成的 `CAPABILITY_TOKEN`。`WORKSPACE_PORT=15173` 用于应用的 Host/Origin 白名单；服务器不运行 Vite，也不另开 `15173` 端口。用户服务启用 linger，主机重启后可自动启动。

## 更新部署

从 Windows 项目目录运行：

```powershell
pwsh -NoProfile -File .\scripts\deploy-haizhizi-server.ps1
```

脚本部署当前 **Git HEAD 已提交代码**，不把工作区未提交修改、密钥、整个 `data/local`、依赖缓存或其他项目复制到服务器。它校验 SSH 主机指纹、源码包 SHA-256 和 Node 官方 SHA-256，再安装 `package-lock.json` 与 `requirements.lock.txt` 锁定依赖、构建前端并检查服务。已有 `shared/server.env` 和 `shared/data` 保留。

源码部署与真实项目数据迁移分别处理。初次部署生成空运行库；项目材料、来源和模型历史应由获授权的数据迁移恢复，不把工程样例算作真实项目。

2026-10-15 已采用 PGlite 官方 `dumpDataDir` 导出与恢复接口迁入原工作台数据，核对结果为 **16 个项目、21 份文档、28 张经验卡**，同时恢复原文件和地图配置；服务器展示的是迁移项目，没有重新填入默认夹具。

## 模型与地图配置

API 密钥和地图服务配置只保存在服务器配置或运行数据中，不写入前端、源码包和本说明。将获授权的 DeepSeek/Qwen 配置写入 `shared/server.env` 后，重启两个服务：

```bash
systemctl --user restart haizhizi-capabilities.service haizhizi-host.service
```

2026-10-15 已安全配置获授权的模型密钥。服务器真实调用 Qwen 模式判定接口成功，求是村资料版本为 `2`，结果为 `completed`；由于模式置信度未达到阈值，程序保留“先调查、模式尚不确定”，没有生成确定拆建结论。

DeepSeek API 的 DNS 可解析，但一次带身份认证的模型列表请求在 TCP 443 连接阶段超时，未到达 TLS 或认证响应；服务器上的 DeepSeek 新生成和联网搜索尚待网络恢复。Node 官方站、npm、PyPI 可访问。未修改服务器 DNS、代理、防火墙或全局网络设置。已有迁移方案、原文检索和专业计算可直接查看；新环境仍需自行配置模型密钥。

## 日常维护

```bash
systemctl --user status haizhizi-host.service haizhizi-capabilities.service
journalctl --user -u haizhizi-host.service -u haizhizi-capabilities.service --since today
curl -fsS http://127.0.0.1:4310/health
curl -fsS http://127.0.0.1:4311/health
```

备份前停止两个服务，再备份 `shared/data` 与权限受控的 `shared/server.env`；PGlite 文件不在写入期间直接复制。恢复到同一应用版本后启动服务。详细的本次版本、健康检查、监听地址和访问结果记录于 `research/test_results/server-deployment-20261015.json`。
