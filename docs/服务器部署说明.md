部署目标为 `zhuhangcheng@10.70.223.113`，Ubuntu 24.04 x86_64。应用沿用现有 Node host、Python 专业能力和 PGlite 数据库，前端使用生产构建。当前采用校园协作工作区，校园网中能够到达该入口的使用者可查看、上传、编辑并开展模型研究；Node/Python 服务保持回环监听。

## 打开服务器工作台

浏览器直接打开 **http://10.70.223.113/**。校园协作模式恢复项目上传、编辑、保存、模型研究和原有业务入口，不要求管理员登录或单台写入设备白名单。

使用者共用工作区，资料按项目、来源类别和版本管理。“内部资料”表示材料来源与项目范围，当前模式采用共享访问范围，并未建立人员身份或企业隔离账户。

SSH 隧道作为备用访问方式，在有服务器 SSH 权限的电脑运行并保持连接：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 15173:127.0.0.1:4310 zhuhangcheng@10.70.223.113
```

随后打开 **http://127.0.0.1:15173/**。本机研发页面 `5173`、SSH 备用入口 `15173` 与服务器 IP 页面可以同时保留。

## 校园协作配置

`shared/server.env` 中设置 `COLLABORATIVE_WORKSPACE=true`。它优先于旧管理员密码哈希和 `PUBLIC_READ_ONLY` 设置；旧哈希继续保留供配置回退，当前不启用账号门。环境文件权限仍为 `600`，API 密钥保留在服务端。

`/api/session` 返回 `deployment=campus_collaborative`，并在 `authentication` 中返回 `enabled=false`、`public_read_only=false`、`collaborative_workspace=true`。这些字段说明工作区运行方式，不代表已识别访问者的人员或企业身份。

内部资料用于模型需同时满足服务端 `ALLOW_INTERNAL_MODEL=true` 与本轮的 `allow_internal_ai` 显式选择。材料导入保存项目、来源类别与原文定位；上传时间和材料形成日期分列，填写的材料日期标记为 `user_declared`，未知日期保留为空。仅导入文件不代替本轮模型使用选择。

两个服务共享随机生成的 `CAPABILITY_TOKEN`。`WORKSPACE_PORT=15173` 用于应用的 Host/Origin 白名单；服务器不运行 Vite，也不另开 `15173` 端口。用户服务启用 linger，主机重启后可自动启动。

`TRUSTED_PUBLIC_ORIGIN=http://10.70.223.113` 只授权这一入口的 Host/Origin。nginx 保留浏览器原始 Host 与 Origin，覆盖客户端伪造的转发信息；不把外部 Origin 改写为本地地址。流式响应关闭代理缓冲，读取超时 300 秒，上传体积上限 12 MB，应用自身仍按原有材料大小上限处理。

校园协作入口取消旧的写入设备与请求方法限制，上传、编辑和研究请求到达原业务接口。Host/Origin 白名单、工作台 CSRF 请求标识与校园 IP 监听保持；API 与地图代理按实际来源 IP 限速 10 次/秒，突发容量 40。模型使用、资料范围及每轮选择继续由业务接口核对。

## 更新部署

从 Windows 项目目录运行：

```powershell
pwsh -NoProfile -File .\scripts\deploy-haizhizi-server.ps1
```

配置或更新校园协作入口时运行：

```powershell
pwsh -NoProfile -File .\scripts\configure-server-ip-access.ps1 -CollaborativeWorkspace
```

入口脚本核对目标 IP 和已记录的 SSH 主机指纹，从 Ubuntu 软件源安装 nginx；安装期间阻止默认站自动启动，核对发行版默认站后保留备份并停用其链接。`nginx -t` 通过后才启用入口。协作选项保存 `TRUSTED_PUBLIC_ORIGIN` 和 `COLLABORATIVE_WORKSPACE=true`，保留旧哈希；应用宿主重启后读取运行方式。脚本不更改 UFW、DNS 或系统全局代理。

入口回退时先停止 nginx，再从本次 `shared/nginx-backups` 恢复先前配置及链接，检查监听范围并通过 `nginx -t` 后重新启动；不要直接启用发行版的全地址默认站。

脚本部署当前 **Git HEAD 已提交代码**，不把工作区未提交修改、密钥、整个 `data/local`、依赖缓存或其他项目复制到服务器。它校验 SSH 主机指纹、源码包 SHA-256 和 Node 官方 SHA-256，再安装 `package-lock.json` 与 `requirements.lock.txt` 锁定依赖、构建前端并检查服务。已有 `shared/server.env` 和 `shared/data` 保留。

源码部署与真实项目数据迁移分别处理。初次部署生成空运行库；项目材料、来源和模型历史应由获授权的数据迁移恢复，不把工程样例算作真实项目。

2026-10-15 已采用 PGlite 官方 `dumpDataDir` 导出与恢复接口迁入原工作台数据，核对结果为 **16 个项目、21 份文档、28 张经验卡**，同时恢复原文件和地图配置；服务器展示的是迁移项目，没有重新填入默认夹具。

工作台文件存储另外通过 `scripts/sync-workbench-files.ps1` 增量迁移：`map-screening` 223 份、`sessions` 472 份、`corpus` 50 份、`intelligence` 5 份，共 **750 份文件、45,194,704 字节**，本次全部新增，0 相同、0 冲突。逐文件 SHA-256 与清单、发布读回一致，新目录权限 `700`、新文件 `600`。脚本只处理这四个目录；重复执行时跳过相同文件，不覆盖同路径不同内容，而将传入版本另存 `shared/incoming/migration-conflicts`。这一步不复制数据库、blobs 或其他项目。
