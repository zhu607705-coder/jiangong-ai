浏览器直接打开 **http://10.70.223.113/**。校园访客可查看项目、资料、已有研判及报表，并使用已审核的原文查询和临时计算；保存、上传、修改配置和调用模型研究需要管理员权限。

管理员账号为 `zhuhangcheng`。写入请求同时限制来源为 **`10.194.110.116/32`** 或本机回环地址，并由后端验证管理员会话。管理员换网时用 `AllowedClient` 更新设备白名单；校园访客只读访问不依赖这条设备地址。部署未开放其他应用端口，也未建立多用户账号体系。

SSH 隧道作为备用访问方式，在有服务器 SSH 权限的电脑运行并保持连接：

```powershell

```

随后打开 **http://127.0.0.1:15173/**。本机研发页面 `5173`、SSH 备用入口 `15173` 与服务器 IP 页面可以同时保留。

## 管理员登录与凭据

初始密码保存在部署电脑的 `.cache/server-admin-credentials.txt`，文件被 Git 忽略，Windows ACL 仅授权当前用户。不要把该文件放入源码包、报告或聊天记录。服务器的 `shared/server.env` 只保存管理员账号及带独立盐的 scrypt 密码哈希，权限为 `600`。

首次配置管理员使用：

```powershell
pwsh -NoProfile -File .\scripts\provision-server-admin.ps1
```

脚本生成安全随机密码，输出仅包含账号和本地凭据路径；已有管理员配置时拒绝覆盖。建议首次登录后，通过受信管理终端执行显式轮换：

```powershell
pwsh -NoProfile -File .\scripts\provision-server-admin.ps1 -Rotate
```

密码更新后重启 `haizhizi-host.service` 使服务器配置生效。公开只读模式使用 `PUBLIC_READ_ONLY=true`：后端为访客提供只读会话，按实际副作用审核公开路径；管理员会话才能调用持久写入和模型研究接口。前端隐藏按钮用于说明权限，后端继续独立校验请求。

|---|---|

| 服务配置文件 | `~/.config/systemd/user/haizhizi-*.service` |

| 入口配置备份 | `shared/nginx-backups/<UTC 部署时刻>` |

两个服务共享随机生成的 `CAPABILITY_TOKEN`。`WORKSPACE_PORT=15173` 用于应用的 Host/Origin 白名单；服务器不运行 Vite，也不另开 `15173` 端口。用户服务启用 linger，主机重启后可自动启动。

`TRUSTED_PUBLIC_ORIGIN=http://10.70.223.113` 只授权这一入口的 Host/Origin。nginx 保留浏览器原始 Host 与 Origin，覆盖客户端伪造的转发信息；不把外部 Origin 改写为本地地址。流式响应关闭代理缓冲，读取超时 300 秒，上传体积上限 12 MB，应用自身仍按原有材料大小上限处理。

nginx 允许校园来源的 GET/HEAD，并将其他方法默认限制到管理员设备。以下六类经过审核的纯查询 POST 单独放行：`projects/:id/knowledge/retrieve`、`knowledge/chunks`、`knowledge/groups`、`community-operations/preview`、`experiences/knowledge-match` 以及 `maps/geometry/wgs84`（均位于 `/api/` 下，前五类属于项目路径）。这些操作不保存方案、不触发模型调用。API 与地图代理按实际来源 IP 限速 10 次/秒，突发容量 40；业务后端仍仅公开明确的方法与路径，未审核的 GET 也不会因此获得写入权限。

## 更新部署

从 Windows 项目目录运行：

```powershell
pwsh -NoProfile -File .\scripts\deploy-haizhizi-server.ps1
```

首次配置校园只读入口，或调整管理员写入设备 IP 时运行：

```powershell
pwsh -NoProfile -File .\scripts\configure-server-ip-access.ps1 -AllowedClient 10.194.110.116
```

入口脚本核对目标 IP 和已记录的 SSH 主机指纹，从 Ubuntu 软件源安装 nginx；安装期间阻止默认站自动启动，核对发行版默认站后保留备份并停用其链接。`nginx -t` 通过后才启用入口。它原子保存 `TRUSTED_PUBLIC_ORIGIN` 和 `PUBLIC_READ_ONLY=true`，不重启应用宿主，不更改 UFW、DNS 或全局代理。首次接入需同时部署支持公开只读模式的宿主代码，再由宿主重启读取配置。

入口回退时先停止 nginx，再从本次 `shared/nginx-backups` 恢复先前配置及链接，检查监听范围并通过 `nginx -t` 后重新启动；不要直接启用发行版的全地址默认站。

脚本部署当前 **Git HEAD 已提交代码**，不把工作区未提交修改、密钥、整个 `data/local`、依赖缓存或其他项目复制到服务器。它校验 SSH 主机指纹、源码包 SHA-256 和 Node 官方 SHA-256，再安装 `package-lock.json` 与 `requirements.lock.txt` 锁定依赖、构建前端并检查服务。已有 `shared/server.env` 和 `shared/data` 保留。

源码部署与真实项目数据迁移分别处理。初次部署生成空运行库；项目材料、来源和模型历史应由获授权的数据迁移恢复，不把工程样例算作真实项目。

2026-10-15 已采用 PGlite 官方 `dumpDataDir` 导出与恢复接口迁入原工作台数据，核对结果为 **16 个项目、21 份文档、28 张经验卡**，同时恢复原文件和地图配置；服务器展示的是迁移项目，没有重新填入默认夹具。

工作台文件存储另外通过 `scripts/sync-workbench-files.ps1` 增量迁移：`map-screening` 223 份、`sessions` 472 份、`corpus` 50 份、`intelligence` 5 份，共 **750 份文件、45,194,704 字节**，本次全部新增，0 相同、0 冲突。逐文件 SHA-256 与清单、发布读回一致，新目录权限 `700`、新文件 `600`。脚本只处理这四个目录；重复执行时跳过相同文件，不覆盖同路径不同内容，而将传入版本另存 `shared/incoming/migration-conflicts`。这一步不复制数据库、blobs 或其他项目。
