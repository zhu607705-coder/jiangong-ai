# 服务器部署与访问

部署目标为 `zhuhangcheng@10.70.223.113`，Ubuntu 24.04 x86_64。应用沿用项目现有 Node host、Python 专业能力和 PGlite 数据库，前端使用生产构建。浏览器优先通过服务器 IP 访问；nginx 只向已授权的操作者地址提供入口，Node/Python 服务保持回环监听。

## 打开服务器工作台

浏览器直接打开 **http://10.70.223.113/**。当前访问白名单为操作者地址 **`10.194.110.116/32`** 与本机回环地址，其他来源拒绝。访问需要处于能够到达该服务器的网络；换网导致来源 IP 改变时，按新的明确授权更新这一条白名单。

该部署同时使用来源地址白名单与管理员登录，管理员账号为 `zhuhangcheng`。服务器入口仅监听 `10.70.223.113:80`，没有对全部校园网地址开放应用。

SSH 隧道作为备用访问方式，在有服务器 SSH 权限的电脑运行并保持连接：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 15173:127.0.0.1:4310 zhuhangcheng@10.70.223.113
```

随后打开 **http://127.0.0.1:15173/**。本机研发页面 `5173`、SSH 备用入口 `15173` 与服务器 IP 页面可以同时保留。

## 管理员登录与凭据

初始密码保存在部署电脑的 `.cache/server-admin-credentials.txt`，文件被 Git 忽略，Windows ACL 仅授权当前用户。不要把该文件放入源码包、报告或聊天记录。服务器的 `shared/server.env` 只保存管理员账号及带独立盐的 scrypt 密码哈希，权限为 `600`。

首次配置管理员使用：

```powershell
pwsh -NoProfile -File .\scripts\provision-server-admin.ps1
```

脚本生成安全随机密码，输出仅包含账号和本地凭据路径；已有管理员配置时拒绝覆盖。建议首次登录后，通过受信管理终端执行显式轮换：

```powershell
pwsh -NoProfile -File .\scripts\provision-server-admin.ps1 -Rotate
```

密码更新后重启 `haizhizi-host.service` 使服务器配置生效。首次接入管理员功能需同时部署统一认证版本，页面资源、查询和修改接口均由后端验证会话，前端登录界面仅负责提交凭据。

## 服务与目录

| 项目 | 路径或配置 |
|---|---|
| 部署根目录 | `/home/zhuhangcheng/apps/haizhizi` |
| 当前代码 | `current`，指向 `releases/<Git commit>` 或带部署时间后缀的版本目录 |
| Node 24 | `toolchain/node`，指向官方固定版本目录 |
| Python 环境 | `current/.venv` |
| 运行数据库、项目与材料 | `shared/data` |
| 服务端配置 | `shared/server.env`，权限 `600` |
| Node 服务 | 用户服务 `haizhizi-host.service`，`127.0.0.1:4310` |
| Python 服务 | 用户服务 `haizhizi-capabilities.service`，`127.0.0.1:4311` |
| 服务配置文件 | `~/.config/systemd/user/haizhizi-*.service` |
| IP 入口 | 系统服务 `nginx.service`，`10.70.223.113:80` |
| 入口配置 | `/etc/nginx/sites-available/haizhizi.conf` |
| 入口配置备份 | `shared/nginx-backups/<UTC 部署时刻>` |

两个服务共享随机生成的 `CAPABILITY_TOKEN`。`WORKSPACE_PORT=15173` 用于应用的 Host/Origin 白名单；服务器不运行 Vite，也不另开 `15173` 端口。用户服务启用 linger，主机重启后可自动启动。

`TRUSTED_PUBLIC_ORIGIN=http://10.70.223.113` 只授权这一入口的 Host/Origin。nginx 保留浏览器原始 Host 与 Origin，覆盖客户端伪造的转发信息；不把外部 Origin 改写为本地地址。流式响应关闭代理缓冲，读取超时 300 秒，上传体积上限 12 MB，应用自身仍按原有材料大小上限处理。

## 更新部署

从 Windows 项目目录运行：

```powershell
pwsh -NoProfile -File .\scripts\deploy-haizhizi-server.ps1
```

首次配置或调整获授权的操作者 IP 时运行：

```powershell
pwsh -NoProfile -File .\scripts\configure-server-ip-access.ps1 -AllowedClient 10.194.110.116
```

入口脚本核对目标 IP 和已记录的 SSH 主机指纹，从 Ubuntu 软件源安装 nginx；安装期间阻止默认站自动启动，核对发行版默认站后保留备份并停用其链接。`nginx -t` 通过后才启用入口。它不重启应用宿主，不更改 UFW、DNS 或全局代理。首次接入需同时部署支持 `TRUSTED_PUBLIC_ORIGIN` 的宿主代码。

入口回退时先停止 nginx，再从本次 `shared/nginx-backups` 恢复先前配置及链接，检查监听范围并通过 `nginx -t` 后重新启动；不要直接启用发行版的全地址默认站。

脚本部署当前 **Git HEAD 已提交代码**，不把工作区未提交修改、密钥、整个 `data/local`、依赖缓存或其他项目复制到服务器。它校验 SSH 主机指纹、源码包 SHA-256 和 Node 官方 SHA-256，再安装 `package-lock.json` 与 `requirements.lock.txt` 锁定依赖、构建前端并检查服务。已有 `shared/server.env` 和 `shared/data` 保留。

源码部署与真实项目数据迁移分别处理。初次部署生成空运行库；项目材料、来源和模型历史应由获授权的数据迁移恢复，不把工程样例算作真实项目。

2026-10-15 已采用 PGlite 官方 `dumpDataDir` 导出与恢复接口迁入原工作台数据，核对结果为 **16 个项目、21 份文档、28 张经验卡**，同时恢复原文件和地图配置；服务器展示的是迁移项目，没有重新填入默认夹具。

## 模型与地图配置

API 密钥和地图服务配置只保存在服务器配置或运行数据中，不写入前端、源码包和本说明。将获授权的 DeepSeek/Qwen 配置写入 `shared/server.env` 后，重启两个服务：

```bash
systemctl --user restart haizhizi-capabilities.service haizhizi-host.service
```

2026-10-15 已安全配置获授权的模型密钥。服务器真实调用 Qwen 模式判定接口成功，求是村资料版本为 `2`，结果为 `completed`；由于模式置信度未达到阈值，程序保留“先调查、模式尚不确定”，没有生成确定拆建结论。

DeepSeek API 的 DNS 可解析，但一次带身份认证的模型列表请求在 TCP 443 连接阶段超时，未到达 TLS 或认证响应；服务器上的 DeepSeek 新生成和联网搜索尚待网络恢复。Node 官方站、npm、PyPI 可访问。未修改服务器 DNS、代理、防火墙或全局网络设置。已有迁移方案、原文检索和专业计算可直接查看；新环境仍需自行配置模型密钥。

## 日常维护

```bash
systemctl --user status haizhizi-host.service haizhizi-capabilities.service
sudo systemctl status nginx
sudo nginx -t
journalctl --user -u haizhizi-host.service -u haizhizi-capabilities.service --since today
curl -fsS http://127.0.0.1:4310/health
curl -fsS http://127.0.0.1:4311/health
```

备份前停止两个服务，再备份 `shared/data` 与权限受控的 `shared/server.env`；PGlite 文件不在写入期间直接复制。恢复到同一应用版本后启动服务。部署与迁移记录见 `research/test_results/server-deployment-20261015.json`，IP 入口配置与集成结果见 `research/test_results/server-ip-access-20261015.json`。
