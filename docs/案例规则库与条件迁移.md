# 案例与规则沉淀、条件匹配和保底研判

2026-10-09更新：任何真实模式的案例/规则命中都先交现有Agent研判，程序只负责取证、引用/条件核查及硬约束。

本版将同一个经验数据库中的记录按 `knowledge.kind=case|rule` 分成案例库和规则库。一项举措一张卡；档案、原始文档、举措、规则和证据通过 project_id、document_id、card_id/revision、locator/hash 关联。没有另建数据库、解析器或 Agent 调度器。

## 数据沉淀流程

1. 原文保存：复用现有上传/ParserPort，保存原始文件、SHA256、解析定位；HTML/XML公开来源另保留URL、原始字节哈希与许可。
2. 举措拆分：本地识别标签和表格行；显式选择模型时，现有 DSH 按提取 Skill 一次返回最多20张 ExperienceDraftBatch，每篇仍只有一次有界模型提取任务。提取结果为草稿。
3. 原文校验：十字段及适用/排除条件都须有同文档、同版本、同定位的逐字引用。提议、实际决策、实施、结果独立；未记载内容为空。
4. 复核与版本：审核来源类型、字段含义、条件映射、单位和迁移前提。批准后进入可用检索；修改撤销批准，保存 revision/history；撤回和原文漂移会让命中失效。
5. 两路检索：先筛 owner、真实/合成、资料时点、审核状态、源版本和举措编号，再分别比较案例与规则。
6. 研判存档：保存本轮查询、候选、命中条件、差异、迁移判断、所用记录版本、知识来源和最后业务行动。新一轮重新检索；同一运行恢复时重核冻结结果，变化则要求新建研判。

论文/政策提供的方法和条件不升级为当前对象事实，历史案例的住户数、资金和成果也不复制为当前项目值。公共来源经普通上传仍沿用现有内部可见性边界，不自动获得外发或训练权限。

## 一个案例提取格式

完整可填模板：[`case-extraction-template.json`](../data/templates/case-extraction-template.json)。权威定义为 `packages/contracts/schema.json` 的 ExperienceDraft、ExperienceKnowledge、KnowledgeCondition；TS/Pydantic由同一源生成。

| 层 | 字段及用途 |
|---|---|
| 档案 | 所属 project_id；原文 documents/Source；URL、时点、许可、文件版本 |
| 单项举措 | title、project_type、development_mode、stage；knowledge.measure_key/measure_name |
| 决策过程 | decision_question、background、key_conditions、alternatives、proposal、actual_decision、decision_basis |
| 实施与复盘 | implementation、outcome、applicability；缺失值 null，禁止合理补写 |
| 条件与迁移 | knowledge.conditions/exclusions、transfer_notes、origin、evidence_level |
| 定位与版本 | 每条 evidence 的 document_id、version、locator、quote；卡片 status/revision/history |

适用条件示意（这里只说明结构，不是已取得的项目事实）：

```json
{
  "fact_kind": "resident_agreement",
  "label": "居民同意本次举措",
  "operator": "eq",
  "value": true,
  "source_value": "居民已经同意本次分栋施工",
  "unit": null,
  "evidence": [{
    "document_id": "填写实际文档ID",
    "version": "填写实际文件SHA256",
    "locator": "填写实际页、段或行",
    "quote": "填写包含source_value的逐字原文"
  }]
}
```

value 是可比较的归一化值；中文词句映射成布尔时另保留 source_value。程序能核验引用和类型，映射的含义由复核者确认；数值/字符串和单位须原文可追溯。当前不做单位换算，不把未知按false或零分处理。支持 eq/ne/gt/gte/lt/lte/contains，条件不允许任意代码或SQL。

本地材料可用“举措编号、举措名称、知识类型、来源类型、证据级别、适用条件(JSON数组)、排除条件(JSON数组)、迁移边界”标签。条件JSON可省略 evidence，本地提取会绑定该行原文；JSON中写下的条件不会因此自动成为可信历史证据。普通原文可用既有手动整理入口或获准模型提取。

## 相似、相关与迁移分别判断

相似度复用 AIHOT 的字符对词法算法，衡量文本接近程度；不是语义嵌入，也不是可信概率。未给出举措编号时的0.25词法相关门仅是召回配置，未经业务校准；显式编号优先确定关联。

相关性回答“是否研究同一举措或问题”。可迁移性回答“当前对象是否满足逐项适用条件，且明确未触发排除条件”。高相似不能抵消不同对象、冲突、缺项、单位差异或排除条件未知。

每个条件保留 matched/unmatched/unknown/conflict、事实与来源引用及原因。当前事实沿用项目的来源、对象、作用域、时点和 epistemic_status 门；估算、假设、未来资料和对象外事实不参与直接命中。空条件、缺少可引用的做法或不明确的排除项只能作为候选。媒体实施记录可作为历史做法参考，实施原因和实际效果继续独立保留未知。

## 两个命中条件与 Agent 保底

| 案例路 | 规则路 | 路线 |
|---|---|---|
| 命中 | 未命中 | case_hit，Agent基于案例证据研判举措建议 |
| 未命中 | 命中 | rule_hit，Agent基于规则证据研判方法建议 |
| 命中 | 命中 | combined_hit，Agent综合两类依据与推荐差异 |
| 未命中 | 未命中 | agent_fallback，显式运行后调用既有 DSH |

命中在额外外部搜索前分流到一个有界Agent研判任务：先调用knowledge_evidence读取冻结的来源与条件，再生成KnowledgeAgentAssessment。模型调用沿用DSH，不以程序拼装替代真实Agent研判。最终仍执行现有旧改否决和关键缺项门；库命中不等于当前项目已获许可或建议推进。规则有不同推荐时保留方案与分歧，不从自由文本猜测它们一致。

匹配预览只读本地owner范围，不写项目也不调用模型；“基于本次问题研判”是一次显式经验增强运行。普通 automatic 运行仍只使用原始引用公开的记录。匹配无命中但选择离线模式时，仅运行工程检查，fallback_status=offline_only；真实模式不论命中或未命中都需要Agent凭据，没有模型凭据时为 blocked_external。未经许可的内部命中在provider打开前阻止外发，不自动退回程序伪装成功。检索范围超过2000条核验预算时明确要求按举措缩小范围，不把尚未搜索的记录算成未命中。

生成建议和未通过审核的提取结果不自动回写为历史事实、规则批准或训练标签。用户实际执行后，应记录新的决策、实施和结果，由人复核后再沉淀。

## 接口与复用

- `POST /api/projects/:id/documents`：既有上传与解析。
- `POST .../experiences/extract {document_ids,use_model}`：有界举措提取，默认本地。
- `POST .../experiences {draft}`、`.../:cardId/update`、`.../:cardId/review`：保存、版本与审核。
- `GET .../experiences?kind=case|rule`：逻辑分库筛选。
- `POST .../experiences/knowledge-match {query:{measure_key,question}}`：本地条件匹配，返回 `{trace,sources}`。
- `POST /api/projects/:id/runs`：可传 knowledge_query，冻结问题后先双库匹配，必要时保底。
- `POST /api/runs/:id/resume`：重核冻结知识版本；任何真实Agent路线均需模型凭据。
- `scripts/seed-case-library.ts`：把指定本地已捕获原文经现有上传/卡片API沉淀；重复运行按原文与举措复用，不审批、不调用模型、不进行额外网络搜索。

Skill入口为 [case-rule-extraction](../runtime/skills/case-rule-extraction/SKILL.md)，固定版本归属与许可证留在references。借鉴 [nature-paper-card](https://github.com/Yuan1z0825/nature-skills/blob/d5c8baa15d6b1bd44bff07865da83961449da01a/skills/nature-paper-card/SKILL.md) 和 [literature-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/92ace75ac21efe19a620434e0ca4e356081fe807/skills/literature-review/SKILL.md) 的证据规范，未复制其搜索或调度服务。

## 建议和决策的信源约束（2026-10-09）

KnowledgeAgentAssessment包含逐项建议、决策理由与citations{source_id,locator,quote}。建议声明matched_card_ids和matched_condition_keys；验证每张引用卡、每个所声明命中条件的现实来源，不允许仅引用历史卡就证明当前适用。所有来源必须在本轮只读工具提供的集合内，引文须逐字存在于该定位；无法读回的page/table定位不能借用全文另一处真引文。

knowledge_agent_report记录Agent初判、最终行动、程序调整原因与final_citations。最终行动保存精确原文，而不是只保留KB封装定位。实施路径使用Agent建议和下一步行动；原案例原文留在折叠参考区，不继续作为当前方案动作。程序最终门只能保持或收紧Agent行动；同一次运行恢复可复用重新验核的Agent工件，新运行重新研判。

只读工具不提供搜索、shell、任意SQL、业务写入或审核权限。提取和匹配预览仍只读本地；实际研判由用户显式启动。离线模式明确标注未调用Agent，仅验证工程条件与引用，不呈现为Agent决策。

## 2026-10-11实现：动作分块、因素映射、聚类与技能蒸馏

本节将10月10日设计落实到同一Canonical契约、业务数据库和DSH运行时。工作台“项目经验 → 原文举措、导师因素政策与技能蒸馏”可操作公开原件导入、动作切分、因素草稿、导师因素复核、混合距离分组及技能草稿/复核/导出。来源、材料版本和业务审核分别保存；功能通过工程测试不等于导师已确认规则或迁移效果已验证。

### 1. 数据组织：对象背景与措施事件分开

沿用同一业务数据库，组织“对象档案—原文片段—措施事件—因素观测—经验/规则卡—复核—研判引用”的关联。措施事件标识至少绑定project、building/unit或设施、动作类型及研判阶段；相同动作发生在不同对象或年份时分别记录。跨文档关联需要对象、阶段或原文关系的明确依据，不能因名称相似就归并。

对象背景记录土地/建筑/改造范围面积、住户及实际使用人数、适老需求、原有设施、区位与服务条件。措施事件记录采取什么动作、在哪里、何时、投入和来源、数量及服务范围、决策依据、实施状态、实际结果与维护责任。对象背景可被多项措施引用，共享属性不复制为每项措施的工程事实。

面积保留土地面积、总建筑面积、实际改造面积等不同含义。人数区分居民、家庭、受益者、参与调查者和法定决策主体，并保存分母和年份。“地区优势”拆为有来源的服务设施、到达条件、已有组织或工程接口；未核实的“区位优越”只作分析线索。

### 2. Chunk：原文定位层、措施层、检索层

原文定位层继续复用ParserPort：保留标题层级、段落、页码、表格名、表头、行列及单位。原件不改写，引用指向原件版本及精确位置。

措施层按“对象—动作—条件—投入—结果/维护”形成一项举措的语义chunk。电梯加装、坡道设置、管网修复等动作变化，或者对象、阶段、投入归属变化时切分；金额、单位、例外、否定和适用条件需要与所属动作一起保留。跨段的同一举措用多个原文span关联，跨表格的数值必须带表头和单位。

长材料先建立目录和动作索引，再围绕选定举措读取局部正文。正文、表格和图纸说明分开保留定位；超过模型上下文预算时采用父子chunk与链接，不截断后将缺少条件的片段当完整案例。共享总投资等信息保存在对象或工程包层，动作chunk只记录引用及分配状态。

本地分块复用ParserPort和documentSlices，按动作、对象与阶段形成可引用片段；CRE的Line/Text表格镜像不重复计入动作。DeepSeek在已有harness内返回紧凑ActionReviewBatch，以片段ID作语义分类、分组和字段选择；宿主附回不可变原文span及程序提取的因素，逐字核验后保存草稿。每篇模型任务最多3项，未覆盖部分保留原文并说明；每次仅允许一次来源纠错；每项措施独立核验，合格项可保存，未合格项保留明确拒绝原因且不入库，超预算停止外部请求。模型不拥有审核或业务写入工具。每个chunk保存document_id、文档hash、span、classification、对象、阶段和上下文关联，提取流程版本由代码/验证记录保留。

### 3. 因素与投入映射：先登记，再派生

每条拟新增因素观测保存：指标键、原始词句、数值、类型、单位、对象、时期、统计分母、来源span、事实/估算/方案假设/缺失、所关联measure_event、归属状态及复核记录。字段由同一Canonical契约扩展，不能在不同模块再建一份独立格式。

资金至少区分预算、合同额、支付额、拟申请支持、已落实出资、年度运行和大修安排；数量记录电梯台数及楼幢单元、坡道位置及实际工程量、其他无障碍设施种类。建设地点不能使用采购人办公地址替代。

只有原文明确对应的投入才能直接映射到某项措施。整小区总投资未分项时，标为“工程包共享金额、未分配”，不平均分给电梯或适老化设施。需要估算分配时独立保存方法、假设及版本，不更改原始记录。

单台投入、单位改造面积投入、单位受益人数投入等由程序在分子分母范围、时间、单位和费用状态相容后派生。分母缺失不补零；年度维护费不与一次性建设费直接比较。

“归因”分成数据归属、历史决策理由和效果因果三个层次：第一层核对哪笔投入及数量属于哪项措施；第二层只提取原文明确记载的理由；第三层需要前后观测、可比较对象及专业分析等额外证据。措施后出现改善不自动证明改善由该措施造成，观察性资料的机制启发不写成已验证因果。

### 4. 导师筛选因素，形成可版本化的判准

提取和频次统计用于发现候选因素，不能把频繁出现直接解释为关键因素，也不能因出现少而移除法规或安全条件。

| 复核类别 | 用途 | 使用约束 |
|---|---|---|
| 必须遵守 | 明确的安全、权利或专业前置条件 | 保存原始依据、适用范围和审核；不能被相似度或综合分抵消 |
| 关键比较 | 改变举措选择、优先顺序和可迁移性 | 可进入距离和排序，但不单独成为否决条件 |
| 辅助背景 | 支持解释及后续调查 | 不默认进入主排序或行动门槛 |
| 排除/弃用 | 无关、重复、口径不可解释或不适合当前目标 | 保留弃用理由、原记录和版本，退出有效因素集 |
| 待复核 | 尚未决定作用或映射 | 不自动提升为业务规则 |

导师与相应专业人员复核因素定义、单位、适用场景、比较尺度、作用类别和例外。工程权利及审批等仍由相应有权主体确认，导师筛选不替代实际许可。

知识库命中判准与最终项目行动门分开：前者回答某项经验是否适用；后者决定当前方案是否进入专项调查、需补资料或暂缓。相似案例存在不自动满足当前项目的七项前置确认。

### 5. 混合因素聚类与匹配：方案为分层＋Gower型距离＋完整链接

先按导师复核的可比较关系分池，优先区分举措类型、资产对象和提议/决策/实施/结果阶段。新增加梯与既有电梯更新、社区总额与单台费用等不因数字接近进入同一费用比较池。关系尚不明确的记录保留为未归组候选。

数值、类别、布尔和有明确等级定义的因素采用Gower型混合距离。原始Gower方法支持混合变量及缺失信息，见[Gower 1971原论文](https://doi.org/10.2307/2528823)；下述距离程序已实现；权重、尺度及覆盖门须在FactorPolicy内明确保存与复核，尚无专业校准结论。

`D(x,y) = Σ(w_k × m_k × d_k(x,y)) / Σ(w_k × m_k)`

数值差异按保存的比较尺度归一化并截断到[0,1]；类别相同取0、不同取1；有专业顺序含义的等级按登记等级范围比较。m_k仅在双方因素有值且口径可比时为1，不把缺失写成零差异。文本检索继续用BM25和既有字符对词法算法提供候选，不将词法相似度当效果概率。

另报共同可比较因素的权重覆盖率。共同因素不足、关键因素未核或存在不能解释的口径冲突时，返回“不可比较/待复核”；不能因为只共享一个因素就报告高度相似。硬排除项由独立条件评价处理，不能作为普通距离被其他因素抵消。

同池采用完整链接层次聚类：只有两个组所有跨组记录可比较且最大距离不超过保存的切分参数时才合并。草稿参数只产生明确标注的预览；运行时仅使用已审核政策。相比沿相近记录连成长链，可限制组内出现差异过大的端点；组的语义名称和边界仍由人复核。不可比较的记录不强制成簇。聚类组织同类证据，不产生来源批准或可迁移许可。

运行时先按现有权限、时点、举措关联和逐条适用/排除条件检索；通过复核的FactorPolicy另将候选组成可解释证据组，并与条件检查和来源一同供Agent读取。当前聚类不替代检索召回，也不直接提升知识命中；资料不足或不可比时保留未分组原因。

采用完整距离矩阵时，n条同池记录、p个因素的两两计算约O(n²p)、矩阵存储O(n²)；每轮扫描矩阵并按最大距离更新的基础实现约O(n³)。先按举措/阶段分池、缓存冻结的距离版本；数据量增长后再依据实际规模优化。当前实现最多处理200条候选并明确标记超量；上述是代码结构对应的复杂度，不是接口耗时或业务效果实测。

因素权重、尺度、最低覆盖和聚类切分值由实际数据与专家标注的可比/不可比样本校准，不凭本轮说明给固定业务数值。评价同时检查专家认可的组内可比性、关键因素覆盖和错误迁移；纯几何聚类指标不替代业务复核。按项目隔离标注与评价，防止同一案例不同chunk进入开发和测试两侧。

### 6. 三种库命中与harness分组研判

1. 案例命中：取得已审核案例及当前条件，DeepSeek解释措施如何迁移、关键差异及下一步。
2. 规则命中：取得已审核的适用方法或规则，DeepSeek结合当前条件组织调查和候选措施。
3. 双路命中：按举措及适用组汇集案例与规则，保留相同建议、差异和冲突；不能按条数投票。

案例和规则都未命中时，DeepSeek在已有DSH/harness里补查原文、分析当前条件并提出带引用和缺项的研究建议。兜底输出的假设不自动成为历史经验或新规则。

程序负责版本/权限/来源准入、类型和单位检查、条件运算及硬约束；DeepSeek负责语义理解、动作分类、案例解释、方案与反证。Qwen现有接入口保留为受限问题判断，模型分工不因本设计自动切换配置。三个命中路线与三类行动建议是两个不同层次。

### 7. 经验蒸馏为技能卡与版本回流

本设计将用户提到的“drill skills”暂解释为distill式经验蒸馏，未声称调用名为drill的外部插件。

技能卡至少包括：适用问题、输入字段、前置与排除条件、应调用的既有工具、输出契约、核验点、反例及失效条件、支持案例与规则版本。先形成草稿，经业务及运行安全复核后作为受控指令使用。原文中的指令不因被提取而取得工具或审核权限。

当前技能草稿由已审核、同项目且同举措的经验卡确定性编译，保存来源卡ID/修订号、输入因素、前提/排除条件、步骤、核验点和反例。复核后可导出SKILL.md；运行时仅注入源卡仍有效且本轮直接命中的技能。工具白名单固定为现有只读knowledge_evidence，不扩大Agent权限；模型式技能蒸馏、外部自动发布和权重训练尚未实现。

版本链保留原件hash、chunk及动作映射、因素字典与审核、距离/分组、经验规则卡、技能卡、研判快照。资料或规则更新后仅重算受影响关系，旧结论和依据保持冻结。新的实际决策、实施和复盘经审核后回流；模型生成、未实施方案和未经许可材料不自动成为训练标签。

### 8. 三维空间证据：单独验证、后置接入

地图交互及3D可视化不作为这轮知识算法的主交付。楼高、建筑密度和可见设施若进入因素集，仍须保存数据来源、时点、坐标、测量/估算方法和误差。

直接展示Google已有Photorealistic 3D Tiles与根据影像自行重建是不同路线。前者需先核目标区域覆盖、API配置与数据署名，目前未确认杭州求是村覆盖。后者需要有相应使用权、不同视点且重叠的影像及尺度/地理校准，可采用SfM恢复相机与稀疏结构，再用MVS建立稠密点云和表面。[COLMAP官方教程](https://colmap.github.io/tutorial.html)说明了该多视角流程；单张卫星截图不足以唯一恢复真实楼高。

Google Maps标准条款限制由相应地图内容生成衍生内容，并明确涉及45°影像重建建筑模型；3D Tiles政策也限制从其瓦片提取或追踪独立3D对象。因此不能直接把下载截图或瓦片重建写成可执行路线，应使用符合条件的官方展示或有另行许可的独立数据。[Google条款](https://cloud.google.com/maps-platform/terms)、[3D Tiles政策](https://developers.google.com/maps/documentation/tile/policies)。本轮未下载Google影像、调用付费服务或启动重建。

建筑密度需要同口径建筑基底及研究边界面积；楼高需要可用地面基准和校准几何。设施外观不能证明完整无障碍、消防或实际运行条件，影像不生成居民人数和改造资金。三维因素经验证后可辅助匹配，不能代替项目原件和现场核查。


### 9. 持久化、接口与复现

`ExperienceKnowledge`内保存`chunks`与`factors`，经验卡修订及原件hash沿用原有链。`knowledge_policies/knowledge_policy_history`保存因素角色、尺度、权重、门槛、复核者及修订；`knowledge_skills/knowledge_skill_history`保存技能及其来源卡版本。修改已审核政策会回到草稿；卡片撤回审核、内容修订或原件hash变化会阻止旧技能继续导出或调用。研究快照保存grouping、factor_policy和skill_refs，恢复时检查冻结身份。

所有接口位于`/api/projects/:id/knowledge`，继承项目owner、会话和CSRF检查：

| 方法与后缀 | 实际作用 |
|---|---|
| GET `pipeline` | 一次读取文档、卡片、因素政策、技能及已有公开来源清单 |
| POST `public-document` | 根据已有source_id保存真实公开正文；复用同hash原件；不接受任意URL或自行公开内部文档 |
| POST `chunks` | 本地切分并保留原文定位，零模型调用 |
| POST `extract` | 默认本地因素整理；显式use_model时进行紧凑分类和一次有界纠错，结果均待复核 |
| POST `policies`、`policies/:id/review` | 保存/复核FactorPolicy；expected_revision阻止覆盖旧版本 |
| POST `groups` | 保存的政策版本下预览混合距离分组与未分组原因 |
| POST `skills/distill`、`skills/:id/review` | 由同举措已审核卡编译技能草稿及复核 |
| GET `skills/:id/export`、`:kind/:id/history` | 导出仍有效的已审核技能及读取项目内修订历史 |

缺失因素不补零；共享工程包资金不分摊到单项；计划、合同、拨付和维护单价分别标记。导师mandatory条件通过当前对象的已核实事实计算，只能收紧最终行动，不抵消既有工程硬门。Agent初判、收紧后的行动及其来源分别保留。

真实材料读回使用`scripts/check-knowledge-public-local.py`及`research/test_results/knowledge-pipeline-public-local.json`。求是村三份已保存公开原文对应99个片段、13张本地草稿和15条因素；本次不生成导师批准、业务门槛校准或成功迁移标签。模型与界面验收另见`research/test_results/knowledge-pipeline.json`。

已有完整DSH返回可通过`scripts/replay-action-review.ts`进行同原件、同版本、同动作索引的复核回放。默认只读，`--write`仅保存通过引用校验的草稿；回放不新增模型请求、不自动审批，原始会话仍保存在本地。已用实际模型返回复核两项草稿并拒绝一项引用错位的措施，见`research/test_results/knowledge-pipeline-model-replay.json`；回放成功不冒充新的端点成功或决策准确率。
