# 案例与规则沉淀、条件匹配和保底研判

2026-10-09更新：任何真实模式的案例/规则命中都先交现有Agent研判，程序只负责取证、引用/条件核查及硬约束。

本版将同一个经验数据库中的记录按 `knowledge.kind=case|rule` 分成案例库和规则库。一项举措一张卡；档案、原始文档、举措、规则和证据通过 project_id、document_id、card_id/revision、locator/hash 关联。没有另建数据库、解析器或 Agent 调度器。

## 数据沉淀流程

1. 原文保存：复用现有上传/ParserPort，保存原始文件、SHA256、解析定位；HTML/XML公开来源另保留URL、原始字节哈希与许可。
2. 举措拆分：本地识别标签和表格行；显式选择模型时，现有 DSH 按提取 Skill 一次返回最多20张 ExperienceDraftBatch，每篇仍只有一次有界模型提取任务。提取结果为草稿。
3. 原文校验：十字段及适用/排除条件都须有同文档、同版本、同定位的逐字引用。提议、实际决策、实施、结果独立；未记载内容为空。
4. 复核与版本：审核来源类型、字段含义、条件映射、单位和迁移前提。批准后进入可用检索；修改撤销批准，保存 revision/history；撤回和原文漂移会让命中失效。
5. 两路检索：先筛 owner、真实/合成、资料时点、审核状态、源版本和举措编号，再分别比较案例与规则。
6. 研判存档：保存本轮查询、候选、命中条件、差异、迁移判断、所用记录版本、知识来源和最后业务行动。新一轮重新检索；同一运行恢复时重核冻结结果，变化则要求新建研判。

论文/政策提供的方法和条件不升级为当前对象事实，历史案例的住户数、资金和成果也不复制为当前项目值。公共来源经普通上传仍沿用现有内部可见性边界，不自动获得外发或训练权限。

## 一个案例提取格式

完整可填模板：[`case-extraction-template.json`](../data/templates/case-extraction-template.json)。权威定义为 `packages/contracts/schema.json` 的 ExperienceDraft、ExperienceKnowledge、KnowledgeCondition；TS/Pydantic由同一源生成。

| 层 | 字段及用途 |
|---|---|
| 档案 | 所属 project_id；原文 documents/Source；URL、时点、许可、文件版本 |
| 单项举措 | title、project_type、development_mode、stage；knowledge.measure_key/measure_name |
| 决策过程 | decision_question、background、key_conditions、alternatives、proposal、actual_decision、decision_basis |
| 实施与复盘 | implementation、outcome、applicability；缺失值 null，禁止合理补写 |
| 条件与迁移 | knowledge.conditions/exclusions、transfer_notes、origin、evidence_level |
| 定位与版本 | 每条 evidence 的 document_id、version、locator、quote；卡片 status/revision/history |

适用条件示意（这里只说明结构，不是已取得的项目事实）：

```json
{
  "fact_kind": "resident_agreement",
  "label": "居民同意本次举措",
  "operator": "eq",
  "value": true,
  "source_value": "居民已经同意本次分栋施工",
  "unit": null,
  "evidence": [{
    "document_id": "填写实际文档ID",
    "version": "填写实际文件SHA256",
    "locator": "填写实际页、段或行",
    "quote": "填写包含source_value的逐字原文"
  }]
}
```

value 是可比较的归一化值；中文词句映射成布尔时另保留 source_value。程序能核验引用和类型，映射的含义由复核者确认；数值/字符串和单位须原文可追溯。当前不做单位换算，不把未知按false或零分处理。支持 eq/ne/gt/gte/lt/lte/contains，条件不允许任意代码或SQL。

本地材料可用“举措编号、举措名称、知识类型、来源类型、证据级别、适用条件(JSON数组)、排除条件(JSON数组)、迁移边界”标签。条件JSON可省略 evidence，本地提取会绑定该行原文；JSON中写下的条件不会因此自动成为可信历史证据。普通原文可用既有手动整理入口或获准模型提取。

## 相似、相关与迁移分别判断

相似度复用 AIHOT 的字符对词法算法，衡量文本接近程度；不是语义嵌入，也不是可信概率。未给出举措编号时的0.25词法相关门仅是召回配置，未经业务校准；显式编号优先确定关联。

相关性回答“是否研究同一举措或问题”。可迁移性回答“当前对象是否满足逐项适用条件，且明确未触发排除条件”。高相似不能抵消不同对象、冲突、缺项、单位差异或排除条件未知。

每个条件保留 matched/unmatched/unknown/conflict、事实与来源引用及原因。当前事实沿用项目的来源、对象、作用域、时点和 epistemic_status 门；估算、假设、未来资料和对象外事实不参与直接命中。空条件、缺少可引用的做法或不明确的排除项只能作为候选。媒体实施记录可作为历史做法参考，实施原因和实际效果继续独立保留未知。

## 两个命中条件与 Agent 保底

| 案例路 | 规则路 | 路线 |
|---|---|---|
| 命中 | 未命中 | case_hit，Agent基于案例证据研判举措建议 |
| 未命中 | 命中 | rule_hit，Agent基于规则证据研判方法建议 |
| 命中 | 命中 | combined_hit，Agent综合两类依据与推荐差异 |
| 未命中 | 未命中 | agent_fallback，显式运行后调用既有 DSH |

命中在额外外部搜索前分流到一个有界Agent研判任务：先调用knowledge_evidence读取冻结的来源与条件，再生成KnowledgeAgentAssessment。模型调用沿用DSH，不以程序拼装替代真实Agent研判。最终仍执行现有旧改否决和关键缺项门；库命中不等于当前项目已获许可或建议推进。规则有不同推荐时保留方案与分歧，不从自由文本猜测它们一致。

匹配预览只读本地owner范围，不写项目也不调用模型；“基于本次问题研判”是一次显式经验增强运行。普通 automatic 运行仍只使用原始引用公开的记录。匹配无命中但选择离线模式时，仅运行工程检查，fallback_status=offline_only；真实模式不论命中或未命中都需要Agent凭据，没有模型凭据时为 blocked_external。未经许可的内部命中在provider打开前阻止外发，不自动退回程序伪装成功。检索范围超过2000条核验预算时明确要求按举措缩小范围，不把尚未搜索的记录算成未命中。

生成建议和未通过审核的提取结果不自动回写为历史事实、规则批准或训练标签。用户实际执行后，应记录新的决策、实施和结果，由人复核后再沉淀。

## 接口与复用

- `POST /api/projects/:id/documents`：既有上传与解析。
- `POST .../experiences/extract {document_ids,use_model}`：有界举措提取，默认本地。
- `POST .../experiences {draft}`、`.../:cardId/update`、`.../:cardId/review`：保存、版本与审核。
- `GET .../experiences?kind=case|rule`：逻辑分库筛选。
- `POST .../experiences/knowledge-match {query:{measure_key,question}}`：本地条件匹配，返回 `{trace,sources}`。
- `POST /api/projects/:id/runs`：可传 knowledge_query，冻结问题后先双库匹配，必要时保底。
- `POST /api/runs/:id/resume`：重核冻结知识版本；任何真实Agent路线均需模型凭据。
- `scripts/seed-case-library.ts`：把指定本地已捕获原文经现有上传/卡片API沉淀；重复运行按原文与举措复用，不审批、不调用模型、不进行额外网络搜索。

Skill入口为 [case-rule-extraction](../runtime/skills/case-rule-extraction/SKILL.md)，固定版本归属与许可证留在references。借鉴 [nature-paper-card](https://github.com/Yuan1z0825/nature-skills/blob/d5c8baa15d6b1bd44bff07865da83961449da01a/skills/nature-paper-card/SKILL.md) 和 [literature-review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/92ace75ac21efe19a620434e0ca4e356081fe807/skills/literature-review/SKILL.md) 的证据规范，未复制其搜索或调度服务。

## 建议和决策的信源约束（2026-10-09）

KnowledgeAgentAssessment包含逐项建议、决策理由与citations{source_id,locator,quote}。建议声明matched_card_ids和matched_condition_keys；验证每张引用卡、每个所声明命中条件的现实来源，不允许仅引用历史卡就证明当前适用。所有来源必须在本轮只读工具提供的集合内，引文须逐字存在于该定位；无法读回的page/table定位不能借用全文另一处真引文。

knowledge_agent_report记录Agent初判、最终行动、程序调整原因与final_citations。最终行动保存精确原文，而不是只保留KB封装定位。实施路径使用Agent建议和下一步行动；原案例原文留在折叠参考区，不继续作为当前方案动作。程序最终门只能保持或收紧Agent行动；同一次运行恢复可复用重新验核的Agent工件，新运行重新研判。

只读工具不提供搜索、shell、任意SQL、业务写入或审核权限。提取和匹配预览仍只读本地；实际研判由用户显式启动。离线模式明确标注未调用Agent，仅验证工程条件与引用，不呈现为Agent决策。
