# 建工 AI
## 片区投资前期研判辅助智能体

把居住需求、项目条件和历史决策经验组织起来，帮助投资拓展与前期策划人员判断：是否值得继续投入尽调资源，下一步最该核实什么。

### 立意与目标

住宅开发与片区更新的前期判断，需要同时理解谁会居住、需要什么服务、项目可以怎样实施，以及企业能否承担相应投入。人口结构、地图点位和历史案例能提供线索，但具体家庭的意愿、支付能力、工程条件与实施安排仍需核实。

项目希望让真实居住需求与公共服务条件进入前期决策，并将企业过去“在什么条件下、为什么选择某个方案、实施后结果如何”的经验转化为可追溯的研究材料，呼应“为人民建好房”的主题。

### 三项核心工作

| 工作 | 要回答的问题 | 当前进展 |
|---|---|---|
| 片区与对象初筛 | 哪些机会值得研究，哪些条件会阻断当前方案？ | 已有地图对象选择、资料组织与老旧小区行动判定流程。 |
| 需求与方案验证 | 人群预算、空间配置与实施条件匹配吗？ | 当前支持旧改静态预算比较；住宅面积配比、套数及客群预算验证仍属研发目标。 |
| 项目经验整理与复用 | 过去的选择基于什么条件，结果如何？ | 已有经验草稿、逐字段原文引用、人工审核和分类检索复用。 |

### 当前原型的演示范围

已形成可运行的本地工作台。首版以杭州翠苑一区的公开历史资料验证地图、证据、旧改研判和经验整理流程。历史招标与改造报道用于研究历史条件，不作为当前参与窗口。

当前六维为居民需求、公共服务、居住工程、实施协同、长效维护、资金交付。它们组织方案观察和待核资料；三类行动建议由明确事实与规则判定，综合适配分不能抵消已确认的否决条件。

### 会议开场参考

我们做的是一个投资前期研究工作台。围绕一个片区，先把需求、工程和实施条件组织起来，判断是否继续尽调；再把历史项目中的决策条件和结果带回来，帮助安排下一步核查。当前已用杭州老旧小区公开案例跑通原型，住宅住房定位与方案反向验证将用真实地块和企业资料继续验证。

## 用户怎样完成一次研究

### 投资拓展与前期策划流程

1. 选择研究对象。在地图选中片区、小区、建筑或已有项目，先查看对象资料、历史阶段、范围及来源时点，再进入详细研究。
2. 整理研究目标与已知条件。建立项目，选择业务方向，补充原始材料和项目内意见。目标家庭、预算等内容须区分已核事实与方案假设。
3. 查看初筛与依据。系统组织现有资料、程序检查和相关经验，展示当前方案的关键条件、阻点与缺项。原型的老旧小区模式输出三类行动之一。
4. 安排优先调查。每项待核事项说明缺什么、影响什么判断、向何处核实，以及补齐后检查什么；可加入本地调查清单。
5. 比较方案并回读来源。当前可调整旧改三类预算、预备费、计划资金与户数，查看总额、假设缺口和户均工程投入；变化仍是方案假设，不自动变成资金已落实。
6. 保存与沟通。查看行动触发依据、历史经验、版本变化和初筛报告，再决定是否继续投入尽调资源。

### 三类行动建议

- 建议进一步尽调：适用规则及继续条件已有对应对象、时点和来源的确认依据。
- 先补充关键资料再判断：没有已证实的独立否决，但关键资料或专业规则还不足以判断。
- 当前条件下暂缓：存在已确认、足以独立阻断当前方案的条件。

未知不按零分处理，方案假设不当作历史事实。用户可从建议回到来源和计算过程。

### 资料维护与专业复核流程

项目负责人登记项目、阶段和资料时点，导入文字、表格及历史文件；核对解析结果、未匹配行、口径差异和原文。经验以候选卡保存，原文没有的理由与结果留空。专业人员确认关键事实、适用规则和经验边界后，已审核经验才可进入检索与复用。

当前部署是单操作员本地工作台。上述是协作职责划分，不表示已经建成多角色团队管理或专业规则发布平台。

## 证据怎样进入判断

### 技术方案

| 环节 | 已有工程能力 | 进一步完善的方向 |
|---|---|---|
| 文档解析 | TXT、Markdown、CSV、PDF、Word、Excel 的文字与表格解析；保存原文定位。 | 扫描件 OCR、复杂表格及业务字段整理。 |
| 数据与证据 | 保存来源、数值、单位、时点、范围和版本；导入结构图与资料覆盖可回读原文。 | 更完整的专业数据口径、核验及发布流程。 |
| 地图与计算 | 高德地图选择对象；坐标与范围处理；旧改静态预算由程序计算。 | 路网可达性、住宅面积配置、套数与静态收支。 |
| 经验检索 | 人工审核后，按项目类型、模式、阶段和问题检索；保留关键条件及引用。 | 用获准历史样本验证条件相似、重要差异与迁移前提。 |
| 规则与模型 | 明确条件由规则判定；DSH 组织专业任务，Qwen 进行结构化分流与有依据的维度观察。 | 企业与专业人员共同复核阈值、规则适用范围和行动质量。 |

### 一项决策经验是一张卡

每张卡记录决策问题、背景目标、关键条件、备选方案、提议、实际决策、决策依据、实施、实际结果和适用边界，并关联所属项目。每个非空字段保留原文、定位与版本；修改后重新进入复核。

提议、实际决策、实施和结果分别记录。系统可以标出待补问事项，不能把未记载的理由补成历史事实。

### 经验怎样用于新项目

先用分类与阶段筛选，再检索决策问题和关键条件。界面并列历史条件、当前待核条件和借鉴前提，帮助用户逐项比较。分类命中不是适用性结论；加入项目的经验仍作为调查线索，不自动成为当前项目的硬约束。

### 等待时先看已有结果

工作台先打开地图和项目本体，辅助资料继续读取；调研取得通过原有来源校验的简报后先展示，引用修复和结构化评分继续进行。接口等待、限流和错误如实呈现，已取得的资料保留。局部计算和接口连通检查与真实业务效果评价分别记录。

## 介绍与工作台一起改进

### 两边如何互相校准

工作台为介绍提供可操作的功能和数据证据：已实现的内容用页面与实际流程说明，研发目标明确下一步资料和验收条件。介绍为工作台提供业务方向：功能改进围绕用户如何完成研究，而不围绕堆叠面板或技术名称。

本次补强历史关键条件与本次待核条件的并列对照，帮助用户从检索结果进入具体调查。住房定位、方案版本和反向验证仍保留为业务目标，需要真实资料及专业口径后逐步接入。

### 核心研发目标：深入验证反过来修正初筛

片区初筛提出需求机会，需求机会形成可检验的目标人群和候选方案；随后用人群预算、现有供给、规划与工程条件、方案经济条件核验。发现不匹配时，调整方案或修正“是否继续尽调”的判断，而不是只在原结论后补一句风险提示。

例如，初筛发现小家庭居住改善可能值得研究。进一步取得调查资料后，如果其预算与当前住房方案不匹配，应指出是哪项条件、哪份资料和哪段计算造成矛盾，再比较面积配置、供给方式或实施节奏。这是待实现和验证的住房定位闭环，不是已经完成的真实项目结果。

### 两个方向各自承担什么

- 从需求到方案：明确人群、范围、时间和承受能力，把需求落实到空间配置、公共服务和具体措施。
- 从方案回到初筛：在统一口径下重新计算预算与供给条件，解释受益范围、投入和实施条件改变了什么，并回查原有判断。

### 下一步可检验的实现边界

1. 以现有方案模板记录措施、工程量、单价、受益范围、资金阶段、维护责任和方案版本。
2. 取得一个获准使用的候选住宅地块，以及对应客群、供给、规划和成本资料，确认一种开发模式和测算口径。
3. 把面积配置、套数和静态收支交给程序，把方案假设与已核事实分开；每次修改保留输入版本、计算结果及依赖关系。
4. 明确哪些条件变化需要重新判断，哪些只改变假设下的测算；由专业人员复核，再演示一次方案调整如何影响初筛。

当前旧改预算调整只影响静态结果，尚未实现住宅住房定位或自动反向改写行动建议。介绍承诺由产品证据校准，产品改进也应围绕上述业务闭环逐步展开。

## 数据、验证与合作重点

### 数据需求与取得方式

| 资料 | 用途与主要渠道 | 关键核查事项 |
|---|---|---|
| 人口与家庭 | 人口普查、年鉴和地方公报，识别人群结构。 | 统计时点、片区范围和家庭口径，不能用网页更新日代替统计日。 |
| 真实居住需求 | 问卷、访谈及获准客群调研，核验意愿、预算和面积偏好。 | 样本代表性、分人群差异及实际支付能力。 |
| 交通与公共服务 | 官方名录、地图服务及现场核查。 | 点位之外的开放时间、服务容量、步行路线和使用条件。 |
| 土地、规划与工程 | 规划公示、原始地块文件、楼栋清单及专业检查。 | 准确边界、权属、建设约束和工程适用范围。 |
| 住房供应与市场 | 公开项目资料、获准房源样本及企业市场调研。 | 挂牌、真实成交、库存与销售阶段分别记录。 |
| 成本、资金与维护 | 企业测算表、批准及拨付文件、专业报价和维护合同。 | 时间、工程标准、完整成本及计划资金与落实资金的区别。 |
| 历史项目经验 | 合作企业获准提供的报告、测算、纪要和复盘。 | 同一项目多阶段材料，连接当时选择与后续结果。 |
| 规则与参考答案 | 企业人员和专业教师访谈、独立核算及复核。 | 适用范围、专业门槛、分歧和评测标签。 |

公开历史资料和地图已可支持流程验证。完整住房需求、工程原件、企业成本与多阶段历史档案仍是合作重点；一个接口没有返回记录，只能说明本次来源覆盖或请求结果，不能断言现实中没有需求或项目。

### 怎么证明系统确实有帮助

拟取得 3-5 个资料较完整的获准历史项目，按项目隔离开发与测试，并限定当时可用资料。设置三组对照：同一底模直接回答；同一底模获得相同原始资料和规则；本系统。

评价字段提取、引用有效性、案例适用性、程序计算、关键缺项识别、行动建议宏平均 F1、错误推进率和用户复核时间，报告样本量及专业分歧。目前工程回归与公开资料演示不能替代这项企业评价。

### 会上介绍与演示重点

先讲投资拓展人员如何把一次“值不值得继续查”变成有依据的行动；再演示地图对象与资料、旧改行动条件、一次预算调整、历史经验和原文。最后说明住房定位双向验证的研发目标，以及希望合作方提供哪些真实资料和专业复核。
