# 侧栏混合检索与 API 索引

2026-10-16。本轮改动限于项目资料检索链路；没有部署服务器、切换 Git 分支或修改项目方案。

## 使用方式

侧栏“直接问资料”默认开启“AI理解、语义召回与回答”。沿用服务端 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL`，密钥不进入浏览器。

第一次提问会自动建立缺少的索引，也可先点“建立 / 更新语义索引”。索引按照项目、拥有者、原文窗口、内容哈希、模型和索引政策保存。再次查询复用已保存索引；新增或改变的原文生成新索引，不冒用旧摘要。

本版语义索引是由现有 DSH / DeepSeek 生成的摘要、概念和常见问法，再由模型进行语义召回。接口实际方法为 `api_semantic_bm25`，没有配置向量模型，也不宣称使用了向量嵌入索引。

## 实际检索流程

1. 从原项目解析快照和已收集来源提取可定位原文，保留文档、版本、对象和日期范围。
2. API 拆解口语问题，生成检索问法与概念；原问题完整保留。
3. 现有 Jieba / BM25 召回最多 30 个候选；API 从语义索引目录独立召回候选。
4. 以排名融合合并、去重并统一排序。自动识别的主题只加分；用户主动指定的资料范围仍生效。
5. 对命中不足的材料补读同文档、同版本相邻片段，保留各自定位。长正文按连续窗口完整建立索引，每窗口最多 4,000 字符，相邻窗口重叠 200 字符。
6. API 根据实际原文生成简短回答。每条引用必须在送入回答的同一原文窗口中逐字成立；不成立的回答条目不作为带据回答展示，原文命中继续保留。
7. 界面提供原文定位、原来源和已有决策位置；缺少资料时给出公开补查问法、阅读重点和内部补充材料。

## 接口

| 接口 | 请求 | 返回 |
|---|---|---|
| `POST /api/projects/:id/knowledge/retrieve` | 原有问题和筛选字段；新增 `use_ai`、`allow_internal_ai` | 原有命中、来源和定位；新增 `assistance` 回答、指引、API与索引状态 |
| `POST /api/projects/:id/knowledge/index` | 资料范围、`include_ai`、`allow_internal_ai` | `status`、`model`、`eligible`、`indexed`、`pending`、`reused`、`warnings` |
| 原有本地 `retrieval.query` | 新增可选 `retrieval_limit`，默认 5，最高 50 | 原有 BM25 命中结构 |

索引存放于同一个 PostgreSQL / PGlite 的 `project_rag_semantic_index` 表。首次使用时建表，新增索引不修改项目资料版本、事实、方案或审核状态。

## API 与资料范围

公开资料可建立 API 索引。内部资料仍走原有文档权限，默认仅在本地参与关键词检索；只有本次勾选允许、并且服务器 `ALLOW_INTERNAL_MODEL=true` 时，才进入模型索引和回答。AI草稿与模拟资料继续由原有筛选明确控制。另一拥有者、另一项目和不同原文内容的索引不会复用。

API 未配置或请求失败时，返回 `keyword_fallback` 和已有原文。索引未处理的窗口返回 `pending`，可继续点击建立索引。关键词服务部分失败时，仍保留其余关键词和语义召回；各路实际状态在界面展开查看。
