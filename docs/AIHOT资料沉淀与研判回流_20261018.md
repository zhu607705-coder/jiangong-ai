# AIHOT资料沉淀与研判回流

AIHOT继续作为本系统公开资料的积累层：发现原文、识别版本、研读分类、关联同一事件及后续进展，再供项目研判调用。本轮恢复这些环节与当前项目流程的连接，沿用现有数据库、工作器、DSH和Decision接口。

## 发现的断点

2026-10-18服务器已有125份公开资料、141个版本，自动采集与自动研读均关闭。资料界面只在地图工具中保留，未出现在“案例与规则”。归集函数仅读项目输入和旧运行记录，遗漏改造研究轮次、方案快照及RAG补查。研究回读将研判日期传给入库时间过滤，导致今天补采的历史公告无法为历史时点问题提供依据。研究归集还截取前12个来源，且未登记来源与项目的关联。

## 同一数据库中的分层

| 层次 | 沿用或新增表 | 保存内容 | 后续使用 |
|---|---|---|---|
| 信源 | `intel_channels`、`intel_observations` | 采集配置、渠道、重复观察 | 更新与来源追踪 |
| 原件与版本 | `intel_documents`、`intel_versions`、`intel_revision_log` | URL身份、原文内容、内容/元数据版本、观察及当前指针 | 原文检索、版本回读 |
| 研读 | `intel_analyses`、`intel_analysis_history` | 分类、对象、日期、引句、入选分与待核问题 | 组织资料与检索提示 |
| 事件与故事线 | `intel_memberships` | 同次发生、后续进展及人工修正关系 | 合并同事件展示，保留不同原件 |
| 项目关联 | 新增 `intel_project_links` | 拥有者、项目、资料版本、原来源ID、库内版本、来自哪个轮次或补查 | 从资料追到项目，从项目回到原文 |
| 执行与回执 | `intel_jobs`、`intel_receipts` | 分批归集、研读任务、处理数量、未纳入原因及模型回执 | 重启后检查、预算等待、避免重复调用 |
| 案例与规则 | 原有经验卡、审核及版本表 | 决策问题、条件、方案、实施、结果与适用范围 | 审核后进入案例库和规则库 |

```mermaid

 A[公开来源与项目历史] --> B[原件与版本]
 B --> C[Decision筛选 / DSH研读]
 C --> D[事件与后续进展]
 B --> E[数据库检索与原文引用]
 D --> E
 E --> F[项目研判与调查]
 F -->|新取得原文和项目出处| B
 F --> G[经验整理与审核]
 G --> H[案例与规则]
 H --> F
```

资料版本包含正文和来源登记元数据变化，不将版本数量视作独立案例或独立证据数量。原文、模型研读和审核经验分别保存。项目关联记录表示资料来源或研究获取关系，不能直接当作正式决策采纳记录。内部材料留在原有项目文档和权限范围，模拟项目不进入公开资料归集。

## 本轮实现

- “案例与规则”默认进入“资料沉淀”，可查看真实原件、版本、已研读、事件及关联项目数量，进入原文版本和来源项目。原案例库、规则库和成本参考保留各自入口。
- 后台归集每批最多10个项目，读取原输入、已有研究原文、改造轮次、方案快照及RAG补查。当前每项目的历史读取窗口为最近100个研究轮次、100份方案快照和1000条RAG补查。归集保留来源与轮次关系，重复执行不重复插入同一关联。历史版本可以入库，不能回滚当前原文指针。
- 新的公开检索结果持续入库，不再截取前12份；项目研究和RAG携带项目与资料版本，自动记录出处。已知库内原文复用时，记录关联而不再复制一份原件。
- 两种时间分别处理：按入库观察时间回放当时快照；按公告发布日期检索当前已取得的历史原文。项目研究采用后者，再核对原文有效期、日期状态与对象范围。城市名称的“市”后缀不再造成同城漏检。
- RAG项目内已有明确原文时保留上一轮快速路径。需要补查时先读沉淀库，所问字段已有原文即可返回；不足时再复用现有公开搜索。
- 自动研读沿用既有开关和每日调用预算。额度不足的任务延至次日，不阻断其他归集或索引任务，不把等待标为完成。原有调用回执、人工事件修正和审核边界保持。

归集自身不调用模型。“归集并研读一批资料”最多安排8份，仍受每日预算约束。持续采集与自动研读是两个开关；不因恢复资料库而自动开启所有站点抓取。

## 验证与部署回执

测试覆盖历史版本不覆盖当前版本、发布日期与观察时点、同城名称兼容、私有材料与其他拥有者排除、超过12份来源入库、项目关联幂等、模型预算等待及原有RAG快速路径。真实入库统计、单条原生研读、页面和项目历史不变检查分别保存在 `research/test_results/aihot-closure-*`。
