# LLM Wiki 与 Topic 主题沉淀试点

参考：[Karpathy 的 LLM Wiki 原始说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)。借用原件保持不变、模型维护知识页、索引/规则/修订日志持久保存的思路，没有复制第三方代码。

本轮先做二次供水、加装电梯、社区食堂三个主题，入口在案例与规则 → 资料沉淀 → 主题 Wiki。Topic表示跨项目的同类问题；AIHOT原有事件/故事线仍表示同一对象或直接后续，两者不合并。

主题页组织跨材料认识、案例差异、材料分歧、推理线索与下一步内部调查。每条认识保留原件ID、版本、逐字连续引文、行号与UTF-16区间。无法核实的条目转为待补问题，其余条目继续呈现。不同对象、地区、年份、阶段和工程范围的金额差异不能直接构成冲突或统一成本。

公开原文通过既有检索窗口召回，按主题从当前窗口优先选12份，每份最多3个原文窗口；页面显示匹配量、采用量和窗口是否截断。使用documentSlices/semanticWindows，不引入第二套切片或搜索客户端。资料、模型路由、提示与结构变化均进入输入快照；旧页保留，页面提示新增资料待整合，用户按需发起修订。

使用同一个IntelRepository数据库，在其上增加intel_topic_pages版本表。整理任务使用原intel_jobs与intel_receipts，复用DSH。每次整理至多一次模型任务，同输入已有成果直接复用；读取/刷新页面不调用模型。与单篇研读共用现有40次日限额；没有新增每条采集资料自动触发一次编纂的循环。

服务器文件位于现有数据根目录下corpus-public/wiki：AGENTS.md维护约定，index.md主题入口，log.md修订记录，topics/主题ID/快照/page.md和page.json为不可变成果。现有documents原件目录不改。网页可下载Markdown和JSON，展开引文或跳到原始来源；现有“查找主题原文”继续使用原检索页面。

此试点尚未将派生主题文字注入项目事实或正式判定规则。跨文本概括由模型产生，程序核对引用与版本；是否构成专业结论仍应结合具体对象、内部材料和适用条件。内部/合成/signal_only材料不进入公共主题页，原件访问范围变化会撤下对应公共派生页。

验证分为合成契约、真实模型试编及正式页面三类，各自回执记录在research/test_results/topic-wiki-*。合成检查不代表真实模型表现或企业效果。
