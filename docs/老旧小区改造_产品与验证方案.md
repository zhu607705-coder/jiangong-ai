# 老旧小区改造前期研判辅助智能体

更新日期：2026-10-10。本文是当前产品与验证规范，依据用户项目构思及已核对的公开来源修订。各功能的实际完成状态以工程文档、代码与测试记录为准；本方案不声明下述模块全部已经实现。

## 1. 项目定位与首版范围

项目面向老旧小区改造的前期策划、工程实施与社区协同人员，围绕老旧小区及其周边片区，组织居民需求、房屋与市政设施、公共服务、居民治理、资金安排和后期维护资料，辅助确定需要改什么、居民影响与实施条件，并安排专项调查，以及下一步优先核实什么。真实居住需求与公共服务条件进入前期决策，呼应“为人民建好房”的大赛主题。

老旧小区改造涉及多来源、多时点、多空间尺度的资料。居民问卷、统计资料、房屋鉴定、改造方案和财政文件各有适用范围，不能用街道人口代替某栋住户，也不能用历史工程结果证明当前方案可实施。企业历史调研报告、工程量及测算表、会议纪要与复盘材料则包含分散的选择条件和实施结果，需要沉淀为可检索、可复用的决策经验。

首版只选择一种改造模式：**老旧小区综合整治提升**。以杭州西湖区翠苑街道翠苑一区作为真实公开历史验证案例，验证片区初筛、改造需求与定位深入验证、一次改造方案调整、经验整理与复用、初筛简报输出。案例已有历史实施和后续改善记录，不作为当前开放招标或获准开发的机会。拆改结合、自主更新及新增住宅开发需各自的产权、规划、资金和专业规则，留待具备材料后单独验证。

改造定位承接原构思中“住房定位”的深入验证作用：针对初筛发现的居民生活问题，核对目标人群、服务短板、工程适修条件、实施组织与资金承受能力是否匹配。调整方案后重新计算，必要时反向修正初筛建议。

## 2. 六维观察与资料口径

六维是产品组织业务判断的视角，不是政府公布的六项打分标准。浙江导则的“六个有”是改造目标；2026 年杭州体检指南公开报道中的四大维度是建筑本体、基础设施、环境秩序、长效运维，二者不应被改写成产品的评分依据。[S2][S5]

| 维度 | 核心问题 | 优先资料及口径 |
|---|---|---|
| 居民需求 | 谁遇到什么问题，改造优先级及承受能力如何 | 普查、统计公报、获准使用的住户调查、访谈和问卷；记录样本、年龄口径、调查时间、楼栋/小区范围、一般或紧急需求、出资与物业费承受能力 |
| 居住工程 | 当前方案能否满足房屋、消防和市政安全前提 | 原设计及竣工图、房屋鉴定、现场测量、管网检查、隐患台账；结构、荷载变化等需有专业依据，地图或照片不构成安全鉴定 |
| 公共服务 | 既有服务的可达性、容量、开放条件是否满足居民需求 | 官方设施名录、地图路线与现场核查；区分设施存在、可到达、可使用及容量，统计年鉴与现场记录分别保存时点 |
| 实施协同 | 谁实施、谁同意、如何协调异议和施工影响 | 权属文件、年度计划、实施主体、方案公示、会议纪要、居民表决、审批或豁免依据、保护对象调查；表决与同意率的具体适用规则由专业人员确认 |
| 资金交付 | 改造支出、获准出资和支付节点是否能衔接 | 工程量、可追溯报价、财政及专营单位出资文件、居民分摊、维修资金余额及使用条件；区分预算、申请、批准、承诺、拨付和实际支出 |
| 长效维护 | 改造后谁接收、谁维护，服务和资金如何持续 | 物业合同、收费协商、设施移交、年度运维预算、公共收益和维修资金续筹、复查及实际工单；不能用建成照片证明长期运转有效 |

每条指标保存名称、数值或缺失状态、单位、统计时点、空间范围、来源、原文定位和版本；分别标记事实、估算、方案假设与缺失项。新增资料先核验再发布版本，重算受影响指标，保留旧记录与变化原因。冲突资料并列保留，不能用“最新抓取”自动覆盖不同口径。

六维图显示业务观察或证据完备程度时，需标明数据定义与来源。正式门槛未复核、资料不足时显示“待核”，数值保持为空，不能把未知画为零分，也不能把业务得分、证据覆盖和可信概率混为一项指标。

## 3. 行动判定与专项调查

智能体负责组织任务、调用工具、检索经验和解释结果。空间可达性、工程量分配、资金分摊及静态收支由程序计算。正式指标口径、阈值、否决条件和适用范围由企业人员及专业教师复核，记录规则来源、审核人、生效时间与版本。原型内未复核的示例规则须标为示例，不能写成现行法规。

按以下顺序输出三类建议之一：

1. **当前条件下暂缓**：已核实且适用于当前对象、模式和方案的条件，足以独立否决当前方案。保存具体条件、证据和规则；这是当前方案的判断，不代表永久否定小区改造。
2. **先补充关键资料再判断**：未发现已证实的独立否决条件，但关键资料或适用规则不足，无法确认继续条件。未知不等于不利事实，也不等于满足条件。
3. **建议开展专项调查**：证据和已复核规则足以支持初筛，且达到预定继续门槛。它授权的业务意义是继续研究，不是正式投资审批、安全认可或自动报批。

硬约束不被综合分数抵消。安全隐患需要转为优先专业核查或处置事项，不能靠较好的居民需求得分将其抹去。资料补齐或方案调整后，只重算依赖变化输入的指标与建议。

每项待核事项说明：缺什么、影响哪项判断、应向哪个责任主体或资料渠道核实、取得什么材料、补齐后重算什么。例如“缺少结构鉴定”应指向取得适用鉴定结论及方案复核，而非由模型估一个安全分。

## 4. 信息沉淀：项目经验提取与复用

以“一项决策经验”为最小单元，保留用户原构思的九项业务记录：所属项目、决策问题、背景目标、关键条件、备选方案、实际决策、决策依据、执行结果、适用边界。工程契约将所属项目放入 `project_id` 等元数据，并把提议、实施、实际结果显式分开，形成以下十个提取字段：

| 字段 | 契约键 | 提取内容 |
|---|---|---|
| 决策问题 | `decision_question` | 当时需要选择或核实的具体问题 |
| 背景目标 | `background` | 居民诉求、企业目标和约束背景 |
| 关键条件 | `key_conditions` | 对选择有影响的现场、资金、权属、组织等条件 |
| 备选方案 | `alternatives` | 材料实际记载的选项，及其提出时点 |
| 提议 | `proposal` | 材料提出的建议或计划，不能作为已形成的决定 |
| 实际决策 | `actual_decision` | 已形成的决定，与提议、计划分别保存 |
| 决策依据 | `decision_basis` | 原文记录的依据；没有记载时标记待补充 |
| 实施 | `implementation` | 已执行动作及实施时点，与决定和结果区分 |
| 实际结果 | `outcome` | 观察到的结果及观察时点；不能把预期效果当实际结果 |
| 适用边界 | `applicability` | 可迁移前提、重要差异及不适用条件 |

卡片元数据保存所属项目、项目类型、改造模式、阶段、研判时点及卡片版本，避免不同项目的字段拼接。

每字段关联一份或多份原材料，保存页码、段落、表格/单元格或其他可回读定位，以及文档版本、提取时间和审核状态。项目档案、文档、经验卡、证据之间建立关联。项目归并、术语统一和冲突检查形成候选记录；经人工复核才成为可用于当前判断的已审核经验。未审核记录可作为检索线索，不能冒充企业正式经验。

提议、实施、实际结果是不同记录；原文没有的理由由模型标记缺失，不补写为历史事实。字段冲突保留各自原文，交由复核处理；更正或撤回后保留版本和受影响引用。用户上传的材料权限、用途许可及项目范围随文档和经验卡传播。

检索先按项目类型、开发模式、所处阶段及研判时点筛选，再结合决策问题与关键条件匹配。返回经验卡、原文依据、相似条件、重要差异和借鉴前提，将经验转为当前调查线索、候选改造措施和待核事项。后续项目形成新决定或复盘材料，经审核入库。不能用案例相似度替代当前工程鉴定或居民表决。

## 5. 调整开发方案与静态测算

改造措施按基础类、完善类、提升类组织：基础类优先处理居民安全和基本生活问题；完善类用于便利和改善需求；提升类涉及公共服务供给等内容。具体归类和支持范围按项目适用文件复核。[S1]

用户通过“调整开发方案”修改经业务确认的措施、工程量或面积配置、单价和资金假设。例如比较“基础安全修缮”“基础修缮加无障碍改善”“加入社区服务设施”三组方案，三组都使用同一现状快照及适用条件。

程序计算工程量乘单价、各措施投入合计、已落实出资合计、未落实资金缺口、居民分摊、年度运维收支等静态量。收入只纳入有经营权和依据的服务费或公共收益；补助申请不能视为到账，造价样本不能冒充项目合同价。无依据的输入标为缺失，用户输入标为方案假设。首版不将售价、新增住宅套数和 IRR 作为综合整治提升的默认结论。

方案页列明单位、测算期、来源、金额类型、公式、假设和未计项目，保存输入输出版本。比较展示哪些措施和资金条件改变、为何改变、哪项建议因此修正。可达性必须说明路网、入口及使用条件；没有数据时不以直线距离代替步行结果。

## 6. 界面与初筛简报

地图固定展示当前小区、楼栋与周边片区的研究范围。行动建议显示支持证据、独立阻断项、关键缺项和优先核查任务。六维图可以进入对应资料及规则；经验参考显示条件相似与差异；方案比较展示静态测算及变化原因；信息沉淀展示项目、文档、经验卡与原文证据的关系。

初筛简报包含对象与开发模式、研判时点、三类行动之一、触发依据、改造需求与工程条件、经验适用前提、方案测算、风险和待核任务。所有页标记真实公开资料、获准企业资料或合成演示输入，保留事实与假设的区别。

## 7. 原型验证与评价设计

拟取得3—5个资料较完整、获准使用的企业历史项目，整理经验样本；截至本文更新，尚未取得该授权样本及完整专业标签，不声明已完成企业评价，也不编造准确率、提效比例或用户复核时间。翠苑一区公开案例用于来源核对与流程验证，不能替代企业历史样本。

测试任务包括事实查询、十字段经验提取、案例适用性判断、计算、关键缺项识别和三类行动判定。以原始材料、独立核算和专业复核建立参考答案，记录复核分歧。按项目隔离开发和测试，同一项目、材料修订及经验卡不能跨集合；限定决策时点可用资料，后续结果只作标签和复盘，不能进入当时输入。

三组对照使用同一底模并记录实际模型标识：直接回答；获得相同原始资料与规则说明的大模型；本系统。对照的对象、时点、资料可用范围和预算分别说明，重点检验结构化处理、工具计算与规则执行贡献，不能让系统组凭额外资料获胜。

| 指标 | 评价要求 |
|---|---|
| 字段提取准确率 | 按十字段及事实/提议/实施/结果类型分别核对，缺失字段不得用合理补写算正确 |
| 引用有效率 | 引用能回读、支持该字段或判断、版本与时点适用 |
| 案例适用率 | 专业人员复核关键条件及重要差异是否足以支持借鉴 |
| 计算通过率 | 结果与独立核算一致，单位、公式、缺项和边界测试同时满足 |
| 关键缺项召回率 | 对参考清单中可能改变行动的缺项统计召回，报告漏项类别 |
| 行动建议宏平均 F1 | 对三类建议分别评价并报告支持样本数，不能只报总体正确率 |
| 错误推进率 | 参考答案不应推进的任务中，被误判为“建议开展专项调查”的比例，列明分母及原因 |
| 用户复核时间 | 统一任务和复核流程，记录实际用时、人员和是否完成，不预填提效结果 |

报告样本量、实际结果、错误案例及适用限制，区分工程检查、来源联通和决策质量。业务得分、证据完备程度与实测表现分别报告。合成任务只验证工程行为；未运行、缺授权或外部依赖不可用不能标记为通过。

## 8. 首版交付与创新边界

首版交付可操作原型、一个真实公开案例的结构化资料、经验卡候选及复核流程、一次可回读方案调整、初筛简报和测试记录。产品重点是：需求与方案条件深入验证能反向修正初筛；建议追溯到事实、规则和程序计算；关键缺项变为可执行专项调查任务；历史决策经验保留证据、结果和适用边界；通过同资料对照验证工程贡献。

尚需专业复核的指标与规则、未获准的企业材料、未经复核的经验候选和待核的项目事实分别记录。后续扩展到其他片区或改造模式，应重新确认资料覆盖、业务规则和评价样本。
