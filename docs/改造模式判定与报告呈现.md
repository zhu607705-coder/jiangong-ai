# 改造模式判定与报告呈现

模式面板在本对象、本资料版本没有完成的 Decision 记录时只展示启动入口。规则里的综合整治保守基线用于条件核验，不直接作为页面的已完成建议。启动、重试、取消或失败均不套用默认方向；此前保存的判定有明确标记。

判定沿用原来的 Decision 调用和条件规则。同一个 POST 接口可用 `Accept: application/x-ndjson` 读取实际阶段事件：

1. 研究对象、资料版本与判定输入整理完成，返回本对象原文数和条件数。
2. 发起 Decision 比较；返回后记录模式初判与依据选择已取得。
3. 复核资料版本和实施条件，保存成功后展示结果。

前端复用现有 `consumeStream`。阶段只按实际后端事件更新，没有计时模拟百分比。旧 JSON 调用仍可用。取消和版本变化停止发布新结果，旧保存记录保持。

结果页默认展开条件。拆建必要性、已满足、未满足、未知和记录冲突分别保留，未满足及冲突项直接显示核验要求和对应记录定位。待审核资料读取现有经验提取草稿队列，显示真实数量、标题和审核入口；草稿没有被改成已核实条件，也没有发送给 Decision。

服务器全局栏移除“查看决策方案”和固定“求是村报告”调试入口，成果页移除写死的求是村 PDF 链接。完成在线研究并保存完整项目结果后，成果页提供本轮调研报告，包括更新判断、投入安排、财务与社会效果、具体改造分项、下一步调查和引用来源。继续复用既有 Markdown／JSON 导出；报告绑定实际项目、资料版本和保存时点。

模式缓存记录调用来源：`explicit_mode`为用户主动判定，`strategy`为整体调研附带结果，历史未标记记录为`legacy`。只有主动判定的完成记录自动恢复到模式结果页；整体调研和旧记录保留在原处。初次点击会实际发起模式判定，重试重新计算，不把其他入口的Decision当成本次判定。
