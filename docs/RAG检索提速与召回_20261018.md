# RAG 检索提速与召回

本轮复用既有 `HybridRetrievalService`、DSH、Jieba/BM25 能力和语义索引仓库。改动集中在检索问答，不自动重跑项目研究或修改事实、方案与历史轮次。

## 延迟来自哪里

服务器同题基线：问“75幢1单元加装电梯预计要花多少钱？”，原文在350.3毫秒返回，完整回答耗时31,013.9毫秒、3次模型调用。旧路径无论是否已明确命中，都先规划问题、再语义判读、最后回答；还可能因为未问的字段缺失继续上网补查。补查追加也没有重新限制结果条数。

## 本轮处理

1. 先使用原有范围过滤及BM25。明确楼幢单元或设施主题已命中时，直接据原文回答，只需一次回答调用；其余问题继续使用已有语义目录判读，无强制模型规划调用。
2. 对口语出资、就餐、上下楼、延期等词语补充有记录的同义词。“拆六建四”保留组合短语，不因切成单字而漏检。精确单元已命中时优先展示对应来源；历史公开来源按当前对象地址重新核对范围。
3. 长文选取与问题相关的连续原文范围，避免只截取文章开头。模型引文仍须在实际送入的同一原文范围内逐字存在，模型摘要不能代替原文。
4. 只有所问的金额、出资、阶段缺失或冲突，以及没有原文命中时，才触发现有公开补查；补查最多12秒，仍沿用原安全公开查询构造。最终结果条数始终遵守请求 `limit`。
5. 已验证引文的直接回答可复用10分钟。缓存位于同一索引表，使用单独 `validated-answer-v1` 政策；键包含拥有者、项目、版本、实际原文内容、范围元数据、筛选、内部资料授权、模型目录及提示政策。变化后重新分析；`refresh:true` 明确跳过复用。失败或无有效引文的兜底回答不缓存。
6. Python仅缓存已授权候选对应的纯文本BM25统计，最多8份、每份不超过100万字符。每次重新执行范围过滤、映射当前来源ID与元数据，避免复用旧来源身份。TypeScript分词复用同样仅保存纯词项。
7. 界面先呈现原文，再更新回答；等待期间支持“提交新问题”和“停止AI补充”。终止不清空已读原文，迟到的旧响应不能覆盖新问题。结果显示原文/完成耗时、缓存状态和模型调用次数。

## 验证口径

- 8个已存公开材料定位问题，同一组来源ID标签留在评测脚本中：宽召回从7/8变为8/8；严格正文主题路径仍为7/8。该结果只衡量来源命中，不等于回答准确率。
- 合同覆盖直接路径、弱命中语义路径、原文连续引用、显式单元排除、权限/版本/文本/模型变化失效、缓存到期与刷新、错误引文不缓存、流式停止及改问。
- 真实端点的前后耗时、缓存重复与项目/研究历史不变检查保存在 `research/test_results/rag-live-*-20261018.json`；部署和页面回执分别记录。服务器延迟随网络和提供方响应变化，小样本计时不作为全站延迟保证。

接口仍为 `POST /api/projects/:id/knowledge/retrieve`，新增可选 `refresh`；返回新增 `routing`、`timing`、`cache`。直接回答的方法标识为 `bm25_with_api_answer`；语义路径继续使用 `api_semantic_bm25`。索引建设留在现有后台任务或手动更新入口，明确命中的提问不再额外排队构建索引。

## 服务器与实页结果

2026-10-18同题实测，旧3次模型调用31,013.9ms；新1次调用5,527.9ms，完成耗时降低82.2%。原文首包417.6ms；同一快照重复查询54.1ms、0次模型调用。另两道关键词问题分别84.3ms、67.2ms。所有最终电梯命中均指向75幢1单元，回答保留54万元草案估算及资金来源口径。

生产前后38个项目及研究历史回读一致。实页已确认回答、缓存状态和原文抽屉，截图位于output/playwright/rag-performance/answer-and-source.png。运行时提交5d100340，前端提交7033f29；最终合并的代码与已部署代码一致，后续提交仅补回执。
