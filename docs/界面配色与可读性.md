# 工作台蓝白配色与可读性

按用户提供的参考界面统一视觉语言：冷蓝页面底色、白色卡片、深蓝正文、亮蓝主要操作，状态与图表使用独立语义颜色。三个全局入口、六个项目页面继续按既有业务职责组织。

| 用途 | 色值 | 应用 |
|---|---|---|
| 主要操作 | `#2363e4` | 主要按钮、当前导航、选中状态、链接与焦点 |
| 正文 | `#172f53` | 标题、数值、主要结论 |
| 辅助文字 | `#5f7190` | 来源、单位、说明 |
| 页面背景 | `#edf3fa` | 内容画布 |
| 卡片背景 | `#ffffff` | 方案、证据、表格与结果 |
| 确认／完成 | `#087f66` | 与既有状态字段对应的完成状态 |
| 待核／提醒 | `#a15e08` | 待核事项和需要关注的条件 |
| 错误／阻断 | `#ce3348` | 实际失败或阻断状态 |
| 推理情景 | `#8171ce` | 推理六维图与情景标签 |

颜色集中维护于 `apps/workspace/src/theme.css`。原样式引用共享变量；`workbench-polish.css` 统一容器、卡片层级与交互反馈。地图 SDK 的颜色参数使用解析后的蓝色色值。

常规正文采用16px，辅助说明尽量使用14–16px；卡片采用18px圆角及轻蓝阴影。桌面内容区扩展到可用宽度，移除底部空带。主操作保持白字蓝底，键盘焦点使用清晰的蓝色描边。

业务金额、评分、来源与六维等级仍取当前项目数据。图表保留蓝、青绿、琥珀、紫等不同序列；状态颜色由既有业务状态决定。

本轮验证记录分别保存构建、主题变量完整性、主要文字色对的对比度和部署后首屏效果。求是村入口供人员手动操作。

## 关键内容的颜色层级

蓝白构成页面底色，决策重点使用完整的状态颜色：

| 内容 | 颜色与呈现 | 对应字段 |
|---|---|---|
| 结构拆建必要性已触发、实施条件未满足、记录冲突、暂缓投入 | 红色标题、标签和左边线，淡红底 | 既有条件组、状态与投资阶段 |
| 尚缺资料、需要核实的条件、前期论证投入 | 橙色标签和边线，淡橙底 | `unknown`、`preliminary` |
| 已满足的实施条件、未触发的拆建必要性 | 绿色标签和边线，淡绿底 | `met`／`unmet`结合必要性或可行性组 |
| 主要操作、当前导航、优先工程分项 | 蓝色 | 操作与优先序 |
| 情景对象、模拟身份 | 紫色 | 情景来源与模拟标识 |

项目总览直接列出当前研究方向的关键实施条件，优先呈现冲突、未满足和待核事项。综合整治显示结构、资金、维护条件；原拆原建从全部拆建条件中提取前三项。已完成研判的原文结论和数据保持原值。

六维卡片、数值、进度条与雷达点同步标色。沿用现有1–5级，按最近整数级展示：1–2为红色弱项、3为橙色中等适配、4–5为绿色较高适配。未知维度显示灰色“—／待评价”。这只是对原有等级的显示编码，实施条件仍由既有规则单独判定。

颜色同时配有可读文字标签；不会把结构问题标为绿色，也不会把“未触发拆建必要性”误标为红色阻断。
