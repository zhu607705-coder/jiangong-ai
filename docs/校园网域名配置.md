## 证书与服务

证书由 Let’s Encrypt YE1 签发，覆盖 `laneanew.cn` 和 `www.laneanew.cn`，到期时间为 **2027-01-14 17:56:55（北京时间）**。证书通过系统信任链和主机名验证，实际访问使用 TLS 1.3。

- 证书链：`/etc/letsencrypt/live/laneanew.cn/fullchain.pem`
- 私钥：`/etc/letsencrypt/live/laneanew.cn/privkey.pem`
- Certbot：`/opt/certbot` 专用 Python 环境，版本 5.8.0。
- DNS 插件：`certbot-dns-aliyun` 2.0.0。
- Nginx：仍只在校园地址 `10.70.223.113` 监听 80、443；应用仍监听 `127.0.0.1:4310`。

HTTPS 域名复用原 Host/Origin 白名单检查。环境配置增加 `https://laneanew.cn` 和 `https://www.laneanew.cn`，保留原 IP 与 HTTP Origin；校园协作、CSRF、限速、上传限制和 650 秒代理等待时间保持。未替换前端或重跑项目研究。

## 自动续签

首次签发通过手动 DNS-01 完成。随后已使用专用阿里云 DNS 身份执行 `certbot reconfigure`，通过 Let’s Encrypt 测试环境的自动验证，并运行 Nginx 检查及重载钩子。正式续签配置已改为 `authenticator = dns-aliyun`，CA 地址仍为正式 Let’s Encrypt 服务。

`haizhizi-certbot-renew.timer` 已启用并处于 active 状态，按**北京时间每天 00:00、12:00** 检查，另加不超过一小时的随机延迟。Certbot 只在证书进入续签窗口时申请新证书；成功后 `haizhizi-nginx.sh` 检查并重载 Nginx。

```sh
sudo systemctl status haizhizi-certbot-renew.timer
sudo systemctl list-timers haizhizi-certbot-renew.timer
sudo systemctl status haizhizi-certbot-renew.service
```

当前 DNS API 的出网路径依赖服务器已有的回环代理 `127.0.0.1:17897`。这是电脑端代理经 SSH 反向隧道提供的出口，**DNS 续签时电脑、代理和隧道需要在线**。网站日常 HTTPS 访问不依赖电脑在线。

服务器直连 Let’s Encrypt 的 IPv6 已实测成功，直连阿里云 DNS 的 IPv4 超时。进一步读取该服务器的浙大校园网认证状态，`/cgi-bin/rad_user_info` 返回 `not_online_error`；本机 OUTPUT 策略为 ACCEPT，UFW 未启用。解除电脑中转依赖需要为服务器完成获准的校园网 IPv4 认证，或配置校方固定代理，目前等待使用者明确可用方式。

## 专用权限与凭据

经用户明确授权创建 `haizhizi-acme`，没有控制台登录权限。自定义策略 `HaizhiziAcmeLaneanewDns` 仅允许该域名的记录查询、添加、删除，以及插件所需的域名列表读取。完整策略见 `docs/deploy/laneanew-acme-dns-policy.json`。

凭据长期保存于 `/etc/letsencrypt/aliyun.ini`，root 所有、权限 0600；云端临时副本已清理，凭据正文未进入代码或交付记录。部署配置位于 `/etc/letsencrypt/haizhizi-renew.env`，仅为 DNS API 指定现有代理。

包装入口 `scripts/haizhizi-certbot.py` 导入原插件，保留其签名与认证逻辑。对清理行为按 TXT 名称、类型和本次验证值精确匹配，避免同名记录含有其他验证值时被误删。相关 3 项定向检查通过。
