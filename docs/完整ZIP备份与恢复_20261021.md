# 完整ZIP备份与恢复

整包包含程序源代码、预构建前端、同一时点的PGlite数据库、原始材料、原文归档、Topic页、项目研判和会话记录。源码版本、快照时间、项目和资料数量、文件散列在包内清单中记录。

生产数据含内部材料，公开GitHub只上传AES-256加密ZIP及不含原文的校验清单。ZIP中只有一个通用名称的`workbench-full.tar`载荷，内部文件名也不在ZIP外层公开。解包密码单独交付到本机私密文件，不进入GitHub、服务器环境或程序配置。

服务器环境文件、地图凭据、API Key、TLS私钥和过时的迁移数据库副本不在包内。当前网站的数据保留，快照完成后生产后台立即恢复；压缩、传输和恢复核验使用独立副本。

## 解包

1. 用7-Zip等支持WinZip AES的工具打开ZIP，输入单独交付的密码，提取`workbench-full.tar`。
2. 再提取tar，得到`workbench`完整目录。也可使用操作系统的`tar -xf workbench-full.tar`。
3. 保留包内`data/local`，其中`postgres`是数据库，`blobs`是上传材料，`corpus-public`是公开原文及主题归档，其他目录保留研判和会话。

## 启动

先安装Node.js24或更高版本、Python3.12或更高版本。Windows运行`start-backup-bundle.cmd`，Linux/macOS运行`sh start-backup-bundle.sh`。启动器复用原`npm run dev`流程；首次运行创建本平台Python虚拟环境，安装`requirements.txt`和`package-lock.json`中的依赖，需要联网。跨平台的Node/Python二进制和现有服务器虚拟环境不混入整包。

默认打开`http://127.0.0.1:5173`。端口4310、4311、5173需空闲；如有冲突，在`.env`中调整PORT、CAPABILITY_PORT和WORKSPACE_PORT。软件只监听本机。已有结果可直接读取；新一轮联网研究需要在新机器配置自己的API和地图服务。

不要把整包直接覆盖到正在运行的另一个数据目录；先在独立目录验证。数据库采用当前锁定的PGlite版本恢复，不能把它当作任意版本原生PostgreSQL的数据目录。依据：[PGlite API](https://pglite.dev/docs/api#dumpdatadir)。

## 快照口径

先预复制文件，再短暂停止主后台并等待数据库正常关闭，在停写期间校验同步全部当前业务数据，完成后立即恢复主后台；Python能力服务和前端静态服务保留。数据源、原文和数据库属于同一停写时点。清单和校验结果分别记录，压缩成功不等于恢复成功。
