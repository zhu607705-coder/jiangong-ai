# 方案生成检查清单与处理规则

适用范围：DSH 更新方案生成、内容核对、保存及成果读取。根据2026-10-16要求，方案内容问题返回结果与后续取证指引，不作为整轮失败条件。

## 一、全部方案内容检查

下列检查继续收集问题，处理统一为：保留模型方案，记录字段位置，列入待核清单。没有把问题改写为核验通过。

## 二、搜索、阅读与内部补充

| 问题 | 继续搜索与阅读 | 内部补充 |
|---|---|---|
| 缺本对象依据 | 项目名＋工程公告、范围、鉴定、规划、居民协商；阅读官方全文与附件 | 对象档案、鉴定报告、既有工程清单 |
| 引文、位置或数量不匹配 | 返回关联原文核对连续原句、定位、数值、单位和阶段 | 未公开设计、测量或台账 |
| 拆建、投入或搬迁条件待核 | 项目名＋资金、结构、规划、安置条件；阅读相应证明 | 鉴定、资金落实、表决与安置安排 |
| 分项和内部数据不完整 | 阅读相近案例的具体整治对象与工程内容 | 居民感受、电梯运行、实际就餐数据 |

结果保留两条路径、模型写出的举措和六维。推理、情景与原文证据按原字段分别显示；实施条件仍从Decision记录读取。

## 四、保留的技术与资料边界

| 项目 | 处理与影响 |
|---|---|
| JSON语法和字段类型 | 先沿现有LiveSession恢复格式；无法解析的数据不能作为完整结构结果渲染。实际原始输出和已得资料保留。 |
| 必需顶层字段 | headline、summary、preferred_mode、rationale、paths、dimensions、next_checks。decision_brief及分项缺失列为待核项。 |
| 嵌套字段和枚举 | 结构契约定义两路径、六维、字符串／数组／数值和枚举类型；完整定义在packages/contracts/schema.json的RenewalStrategy。 |
| 模型未配置、认证、网络或输出截断 | 没有实际完整输出时显示真实运行状态和已得资料，继续使用已有结果。 |
| 搜索零命中 | 保留检索主题，主研判按已有资料和明确前提给出建议。 |
| 项目、拥有者、版本 | 结果、来源及冻结快照只绑定其原项目／版本，不借同名项目或其他拥有者的材料。 |
| 内部材料 | 使用现有本轮授权和可见范围；公开恢复脚本不接收内部材料。 |
| 用户取消／总时限 | 立即停止新工作，保留已存资料、专家记录及之前的结果。 |
| 保存时资料已变 | 结果保留为历史版本，当前页按新基线研究。 |
| 公开读取 | 新advisory-v1结果保留待核项进入成果页；旧严格结果继续兼容。 |

## 六、仍存在的运行边界与已取消要求

- 主链总时限600秒，HTTP请求610秒；用户取消即时停止。公开检索80秒后预留最终综合时间，未执行的查询主题保留。
- 专题并行数最多3。单次来源读取最多10个ID、查询280字符；字符窗口及输出容量沿现有工具定义。它们限制一次工具请求，不限制方案是否可展示。
- 每专家读取2次、模型4次、整轮18次这类次数硬上限已取消；本次不恢复。
- 正文必须写“模拟／假设”等口令词的准入已取消；使用现有结构字段标记来源类型。
- JSON详细字段约束由schema.json完整列出；内容层30类原检查及新增专题回退项全部是待核项。
