# 对象与当前上下文合同

2026-10-17。对应 Pro 架构评审的整轮实施。保留 DSH、Store、原文解析与现有研究轮次，统一对象关系、当前结果、节点恢复、问题覆盖与快速判断。

## 当前实现

“当前分析”由 `resolveCurrentContext()` 统一解析。工作台、项目 Decision 和公开成果入口使用同一结果，不再各自按模型时间、数据库完成时间或轮次号挑一份方案。

项目快照保存项目 ID、资料版本、对象范围哈希、条件哈希与完整输入哈希。哈希基于实际写入数据库的 JSON，包含资料、可见范围与目标条件。仅比较 `context_version` 不能发现的输入变化，也会使旧快照失效。

每次正式研究先在短事务中取得递增请求序号，模型和检索在事务外执行；保存时再次锁定项目并比较完整输入与请求序号。旧请求迟到时仍保存真实输出，但不替换当前指针。新请求失败时继续展示同条件下已有的可用结果。模拟路径独立，不推进真实项目的指针。

新增两张增量表：

| 表 | 保存内容 |
| --- | --- |
| `project_analysis_heads` | 每个拥有者、项目的请求序号与当前分析指针 |
| `project_analysis_attempts` | 冻结上下文、请求序号、研究轮次及终态输出 |

旧数据兼容读取：没有新指针时，按项目、拥有者、资料版本、模拟身份及可用输入快照选择已完成研究；研究结果与独立保存的公开方案分别保留。历史记录不改写。资料缺少不影响条件方案的保存与阅读。

## 对象与证据

复用 `packages/research/evidence.ts` 的行政地址核对，按原文片段区分登记对象、同名候选、明确异地与对标参考。供应商、代理机构的联系地址不作为项目地址。

例如项目登记天津建工新村，而原文明确写杭州市建工新村：该原文仍保留，标为异地参考；不进入天津项目的对象现况与结构条件。需要核对的对象地址进入已有的材料待补充清单，方案仍可返回有前提的建议。新生成方案的模型输入同步使用这一关系。

同名但没有地点冲突的资料标为候选，不能仅凭名字相同宣称完成了物理对象确认。片段读取接口可以独立判断同一文件中的不同案例；混合文件仍需保留原文定位。既有报告中的模型文字不被后台擅自改写，阅读时显示对象待核信息；含明确对象冲突的旧分析不用于新增 Decision 的当前事实判断。

兼容旧项目没有独立城市字段的情形：复用行政地址解析，从地图登记地址或对象名称的明确行政前缀取得地域；搜索词与核对使用同一登记地域，不补写项目原始字段，也不默认为杭州。

Decision 的共享请求入口同步统一到最多 16 题。超过上限在出网前返回输入错误，已有项目工作判断的分组保持原样。

## 节点恢复与执行记录

复用宿主原有后台任务注册表，HTTP 订阅与研究执行分离。`POST research-rounds/:id/start` 在保存轮次、截止时点与 provider 后返回 202；`events` 只订阅，关闭页面不取消任务，`cancel` 才明确停止。旧 `run` 流接口继续兼容。重开页面会订阅当前轮次，执行记录可查看真实已保存节点、复用次数、快照与调用结果。

Store 增加四张表：`research_node_receipts`、`research_round_events`、`research_manifest_versions`、`research_call_receipts`。取证、快照、研究分工、每个专家、补查、综合及费用整理分别保存。短事务认领租约；网络调用在事务外；心跳延长租约；递增 fencing token 阻止失效执行者覆盖新结果。相同输入的已完成专家直接复用，未完成节点继续执行。宿主重启恢复有快照的未完轮次，旧版没有节点快照的记录保留历史。

每轮 provider 与时间预算固定。重启不会悄悄刷新原有预算，停止的轮次不自动重启。每次真实模型及 Search/Fetch 尝试都有回执；客户端失联但服务端结算不明时记为 unknown，不能记零费用。内部来源在节点开始、复用及提交前重新核对。专家结果保留输入 lineage，私有材料影响过的摘要不直接进入额外的公开 Decision 请求；可独立核对的公开专家记录单独重建视图。

## 问题覆盖、补查与原文表示

复合问题先拆字段。例如机电、雨棚、消防通道分别核对金额、金额阶段、资金来源，形成九格覆盖。每格保留来源、连续引句及 supported/conditional/missing/conflicting；有命中不等于全部回答。预算、中标、合同、结算和支付分别保存；金额采用十进制换算，价格年未明确时留空，财政出资不自动解释为已经到账。

旧原文、增量取得和刷新分别计预算。每个检索问题先预留候选名额，再按来源类别及域名分布补足全局额度；十份缓存不会挤掉新证据。专家通过现有 DSH 只读工具提出缺项、检索词与受影响判断，由宿主在公开资料范围内补查；新增 manifest 只使受影响专家重新研究。内部材料形成的调查请求进入内部材料清单，不发为外网搜索词。

RAG 保留既有召回、重排与逐字引用核对。补充原文进入当前项目/上下文的独立来源表，不自动写成事实；零命中仍可给出明确前提、假设与验证办法的条件推理。核验发现、压缩遗漏、费用缺格及专家调查请求都进入已有调查/待补材料入口。

Search 正文、Fetch Markdown 和原始 HTTP 表示各有哈希、提取器版本与 UTF-16 定位。API Markdown 的原文件哈希未知时不伪填。刷新产生新版本，保留旧原文；检索摘要不当原文。既有解析器继续负责原 HTML 等材料，不增加另一套解析框架。

## 独立 Search/Fetch 的取舍

三条路径均挂在原 `ctx.web`：`legacy`、`deepseek_tools`（Search 后 Fetch）、`deepseek_content`（优先复用 Search 正文，必要时 Fetch）。原始 JSON 接口按[官方合同](https://api-docs.deepseek.com/zh-cn/guides/search/)接入，限制查询长度、请求速率和域名并发，保留有界重试及回退。403/404 的来源拒绝不通过改走 HTTP 绕开。

同一组杭州建工新村的三条公开问题、新原文预算四份，实际接口对照如下。样本仅一个对象，不解释为普遍加速率。

| 路径 | 用时 | 取得原文 | 已知预期工具费用 | 费用未知尝试 |
| --- | ---: | ---: | ---: | ---: |
| legacy，首次 | 9.609 秒 | 4 | 模型 token 费用未纳入 | 工具账本不适用 |
| Search＋Fetch，首次 | 82.719 秒 | 4 | 0.020 元 | 3 |
| Search 正文复用，首次 | 1.103 秒 | 4 | 0.015 元 | 0 |
| legacy，复测 | 7.429 秒 | 4 | 模型 token 费用未纳入 | 工具账本不适用 |
| Search 正文复用，复测 | 0.937 秒 | 4 | 0.015 元 | 0 |

直接 Fetch 有三次客户端超时，故默认采用 Search 正文复用，保留其他 provider 供回退和比较。四份固定原文的提取重放识别了九格中的八格；消防通道资金来源未见于所取得正文，进入继续补查。表格读取修正与 provider 耗时对照分别报告，不混成算法准确率提升。

## Decision 与科学性

Decision 继续使用现有 System One 客户端，覆盖六维暂估、研究分工、专家力度、六个页面的下一步、措施与材料优先序。共享入口校验题型、criteria、分布、等级及期望值；独立问题按最多 16 题分组，最多两个并发批次，部分合法答案保留。候选池、实际已评分集合和未评分 ID 单独保存，排序范围明确为 scored_subset。

项目工作判断记录 ordinal rubric、分值方向、对象/资料/目标状态、原始分布及未校准标记。目标权重变化采用同一适配标尺，保留未知维度的区间；正式实施条件始终单独核对。专家时间按问题复杂度、来源规模和已有 p95 记录分配，预留综合时间；历史样本不足时采用明确的默认预算。

上下文压缩保留同源引句及实际阅读范围内的金额、阶段、否定与前提，报告逐字保留比例和遗漏定位。字符压缩率不能单独证明语义不丢失；遗漏片段加入补读任务。模型综合未完成时，宿主按已保存专家记录、原文和明确情景交付结构化条件报告，标记实际整理方式。六维情景和事实现况分别保存。

`scripts/evaluate-research.ts` 支持独立对象标签的 Brier、log loss、RPS、ECE 与准确率；校准集与测试对象不能重合。当前没有独立人工决策标签，产物记录 `insufficient_independent_human_labels`；不会把模型信号当真值训练校准器。公开来源字段覆盖、原生协议可用性与业务判断质量分别评价。

隔离原生实测：一个专家完成三次实际模型调用并使用受限原文读取；零原文综合用时 25.306 秒，生成六项推理维度和五个具体分项，全部没有虚构 source ID 或引句。这是协议与缺项交付验证，未对真实项目自动发起研究。

服务器部署后再测：默认 `deepseek_content` 在 0.689 秒取得一份公开原文；Decision 的 38 项合成协议题按 16＋16＋6 返回，38 项均通过类型与分布核对，总用时 0.416 秒。上述请求均未写入项目或全局知识库。部署前后 38 个项目及研究历史保持一致，具体回执见 `research-complete-deployed-providers-20261017.json` 与运行/界面部署记录。
