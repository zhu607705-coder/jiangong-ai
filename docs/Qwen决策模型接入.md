## 实际接口

用户提供的通用地址 `https://maas.qianwenaiapi.com/compatible-mode/v1` 在本次实测中：`GET /models` 返回 200；`POST /systemone` 返回空的 404。直接读取[官方决策模型 API 页面](https://platform.qianwenai.com/docs/api-reference/decision-model-api)的当前 HTML 后，示例使用以下预览地址；同一把 Key 在这里实测成功：

```text
https://trial.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone
model: decision-model-preview
```

官方搜索缓存与实时页面的地址当时不同。这里只记录本次实际成功的路由，后续地址变化需要重新验证。服务端只接受官方网关地址，禁止附带凭据的 URL 与重定向。

本机 `.env` 保存 `QWEN_DECISION_API_KEY`、`QWEN_DECISION_ENDPOINT`、`QWEN_DECISION_MODEL`、`QWEN_DECISION_ENABLED=true`；不进入 Git 或前端。示例文件只包含空 Key。配置变化后重启本地服务。

## 分工与操作

Qwen 使用 System One 协议，返回分类、概率分布和置信度，不生成说明文字。DSH 仍是唯一运行时：通过它的 ToolRuntime 执行固定输入的 Qwen 能力，再让已有生成模型按结构化判断组织简报。

一次请求并行回答三个问题：下一步操作（choice）、优先调查维度（choice）、证据是否充分（noul）。本版未将 score 用作投资总分。

| 结果 | 产品中的实际操作 |
|---|---|
| 先补证据 | 选定优先核查维度，形成具体调查项 |
| 先核查阻点 | 保留已存在的来源阻点，优先处理对应条件 |
| 进入路径比较 | 在核心条件已有依据时比较研究路径 |
| 复核判断 | 复核来源或低置信判断，再更新研究路径 |

完整项目报告把补证／阻点／复核操作排为第一条调查项，可沿用“加入调查清单”。加入清单只写本地任务，不对外发送或安排实际工程。地图端显示操作及简短下一步，概率与请求记录放在折叠依据中。

## 程序约束

- 条件事实的来源、对象、日期检查继续由原六维检查表负责。Qwen 不生成或改写这些事实，也不直接改地图颜色。
- 已有明确阻点优先；缺少核心依据时不能因高模型概率进入比较。
- 默认置信度阈值 0.8、所选选项概率阈值 0.65、证据充分性阈值 0.75。这是尚待真实案例校准的研究分流规则，不是投资成功率。
- 低置信时保留概率与原始选项，进入补证或复核；已选择的复核不会被误变成普通缺项调查。
- 新供应商只取得公开资料。已有内部文本、内部事实和企业规则不因配置 Qwen Key 自动转发。
- 返回模型、答案类型、选项集合、数值范围、概率和与输入 token 均检查。超时、取消、HTTP 错误、无效 JSON 不当作成功，也不伪装成其他模型的决策结果。
- 单次请求 12 秒上限、输入 160 KB、响应 100 KB。模板包含公开来源与当前事实；最多三个案例仍由既有 Skill 提供给简报阶段。
- 地图摘要64字、项目摘要96字。DSH 不支持的长度关键字转换为模型可见提示，返回值仍按完整契约校验；不裁掉否定句。有界格式修复保留来源和条件。
- 只有对应项目且满足日期要求的原文，才允许模型提出条件因子；没有这种资料时，输出结构不开放因素提取。简报引用使用本轮来源短ID并在宿主还原，案例编号与虚构ID不能混入地点证据。
- 截断的场所总量仍不能参与统计判断；实际返回的地点样本可以支持办公、商业等调查线索。

## 验证与复现

```bash
npm run verify
node tests/browser/map-workspace.mjs
# 已配置密钥后显式运行；调用实际 Qwen API，并生成四个合成场景的记录
npm run test:decision:live
```

四个场景只验证接口和流程行为，不构成投资判断准确率评估。条件齐全的合成样本中，模型仍给出较低置信判断，程序保留复核；未把它改写为高确定性的投资结论。

本次真实链路包括高德场所查询、Overpass 对象分区、Qwen 判断、DSH 简报与杭州公开资料项目研究。详细状态、当前测试计数及证据路径见 `research/test_results/qwen-integration.json`。密钥、完整会话和项目运行原件保留在 `data/local`。
