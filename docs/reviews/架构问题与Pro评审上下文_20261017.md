# 老旧小区更新决策工作台：后端架构与搜索评审上下文

核对日期：2026-10-17。代码基线：`29f5ef08d8c520c09752278574732b53cc28a485`。本轮任务是形成问题清单、比较相近架构并提交网页版 Pro 评审；生产代码和项目资料保持原状。

## 1. 评审目的与约束

工作台辅助政府或企业判断：片区是否需要更新、综合整治或原拆原建哪个方向值得研究、当前投入阶段、财务与社会效果，以及哪些调查最可能改善下一轮决策。项目有六页：总览、资料与条件、改造研判、方案与测算、调查任务、成果与版本。

当前采用 React/TypeScript、Express、PGlite（PostgreSQL 接口）、Python 能力服务。DeepSeek Harness（DSH）是既有生成和专业任务运行时。Qwen `decision-model-preview` 的 System One 返回 choice/noul/score 与分布，不生成解释长文。确定性程序管理金额、范围、来源和正式实施条件，DSH 解释与形成候选措施，Decision 用于快速选择、评分和工作分流。

必须保留：已有模型客户端、Store、原文解析与定位、历史研究轮次、内部材料选择与权限；优先改造现有能力接口，不并排增加第二个调度器、上下文系统或通用搜索客户端。仍应比较替换方案的真实收益和代价，不能把“不换框架”当成拒绝发现结构问题的理由。

缺材料时仍须交付可用的条件方案、明确假设的六维暂估和待补资料。不能把内容缺项或模型低确定性变为整轮失败，也不能将暂估升级为鉴定、资金到账或居民决议事实。真实公开数据为主体；模拟用于交互和流程演示，单独标记。成本预测神经网络是可选辅助，不能代替同工程范围、价格年、金额阶段的成本参考。

## 2. 当前调用链及已确认现象

### A. 搜索与抓取

`runtime/dsh/public-web.ts:mountPublicWeb` 当前挂载 DSH `dsh-web-search-deepseek@0.2.0-rc.1` 与 `dsh-web-fetch-http`。已读本地安装包：Search 走 `https://api.deepseek.com/anthropic/v1/messages` 的 `web_search_20250305`，每个搜索请求经过一个模型回合；Fetch 是普通 HTTP，并在应用侧提取正文。这与独立 `/v1/tools/search`、`/v1/tools/fetch` 不是同一调用路径。

`services/capabilities/research.ts:33-78`：每轮最多6个问法，Search 每次 `maxResults:4`、两个并发；新抓取名额取 `max(0,10-sources.length)`，其中 sources 已先装入缓存和种子原文。因此存在明确的缓存饱和分支：已读缓存达到10份时，虽执行新搜索，却没有新页面的抓取名额。新资料发现与旧资料复用没有独立预算。

`packages/retrofit/renewal-research-plan.ts`：对象轮六个固定主题主要限定 `site:gov.cn`；第二轮固定杭州、上海案例，并把对象的 `site:edu.cn` 费用搜索放在后面。`services/map-screening/renewal-strategy.ts:90-103`：若首轮及前序耗时达到80秒，可跳过第二轮。对大学社区等对象，这种来源分配可能错过本对象教育官网。缺项决定主题顺序，但尚非由每个决策问题的覆盖程度驱动补查。

### B. 本地检索和回答

`packages/experience/hybrid-retrieval.ts` 已有原文先返回、最多3个改写问法/4个子问题、BM25/词项召回、缓存语义摘要、LLM 候选判读、排名融合、原文引用检查；不是“只有关键词、从未采用语义”。但这条链以词项排序缩小语义候选：最多60个窗口、24000字符；未见该链调用向量索引。候选预筛漏掉的内容无法由后续 LLM 选回来。不能在未对比前默认加 embedding 或 GraphRAG。

2026-10-17 在实际网页“直接问资料”提出：机电配套、雨棚、消防通道各自费用、资金来源，金额是预算还是结算？页面返回21份来源中的5条命中、5个回答引文，区分雨棚预算与成交报价、消防通道成交报价，也能显示相关决策位置。说明非供水检索可以工作。与此同时，机电交易公告已命中，主回答对该分项未同样完整列出费用和资金字段，存在组合问题覆盖不足的观察。本次只是一条现场问题，不能据此计算总体成功率。

原问题的后续“公开资料补查”目前是搜索引擎链接；专家本地检索无命中时继续条件推理，但并不会自动申请一轮受控网络补查。因此“给取证指引”和“真正执行补查”要分别设计。

已有离线评测 `research/test_results/research-recovery-retrieval-evaluation-20261016.json` 只含8个归档问题，两个协议的 source-hit@5 均为7/8，model_calls=0。这不是大样本独立 RAG 答案质量评测。

### C. 对象、来源与版本

实际页面当前项目对象登记为“天津市 建工新村”，已存研究内容却含杭州西湖区建工新村、日晖新村材料。现有范围核对并未全链路防止这种关联；不能把它仅归因于模型幻觉，也不能擅自把项目改成杭州。应评审从地图对象、规范标识、跨文本实体到专家来源目录与最终报告的一致性机制，旧报告保留为历史。

项目方案同时存在独立发布缓存与已完成 research_rounds。最近新增跨页 Decision 先只读独立缓存，曾把实际已有方案视为缺失；现已修正为优先读取当前已完成轮次。此现象提示：多个消费者对“当前有效方案”的选择逻辑仍可能重复。

### D. 智能体编排和恢复

`runtime/workflows/renewal-research.ts` 冻结本轮获准来源；动态规划0至3个专业任务，角色为建筑实施、投入价值、居民运营。已有 Decision effort 路由可省去 DSH 规划调用；但 `packages/decision/fast-analysis.ts:decisionResearchPlan` 用角色固定问题生成任务，并按通用角色词项选最多10份来源，可能以速度换掉具体问题规划能力，需要比较验证。

专家只获自身来源的本地 query/offset/limit 只读工具及 structured_output，无 shell/任意文件/外网能力；这是应保留的隔离。若需要追加网络资料，应由宿主接收受限补查申请，再为新来源建立新目录版本，不能让子 Agent 直接继承编程权限或改写已经引用的冻结目录。

`renewal-research-effort.ts` 用来源字符数、问题长度及 brief/standard/deep 调整 token/timeout，固定给综合阶段保留150秒；总方案约600秒。专家失败有局部重试和增加输出空间。这些是工程启发式，尚无按问题价值、风险或预计信息增益校准的资源分配实验。

`evidenceWindows` 保留实际读过的原文和引用附近窗口，字符预算约10000；并没有据此证明所有否定、前提、金额阶段和冲突都被语义保留。实际曾出现压缩后上下文变长，应按全量输入与最终上下文分别测量。

`apps/host/renewal-mode.ts:21-25` HTTP连接关闭会中止请求信号。`apps/host/research-rounds.ts` 启动时将仍为 running 的轮次标为失败，专家中间成果主要随最终 result 保存；有 DSH 会话持久化并不等于业务节点能从最后完成阶段恢复。应比较现有 DSH/Store 的节点回执方案与更持久执行结构，不默认换库。

### E. Decision 的扩大使用与科学性

已实现：地图六维暂估、下一步和缺项优先级、专家 effort；以及一次判断支持项目六页下一步、举措排序和资料优先级，支持三种目标权重预设。项目请求为六页 choice 加十个排序名额，通常5项举措+5项资料；其他条目仍留在原清单。该完整请求在一次线上实测为918 ms；不是整个研究流程的耗时或准确率结果。

18问题的真实请求曾 HTTP 400，项目链现控制为≤16；但共用 `services/capabilities/decision-model.ts:121` 仍允许最多24个问题。不同入口的服务能力限制未统一。请评审怎样统一类型、问题预算、降级、用量、版本和可恢复错误，而非添加更多业务强制门槛。

六维暂估使用模型 score 分布期望转1–5级；工作优先参考分为 score×25。概率合法性、期望一致性和来源定位有校验，但未见这条链上的独立校准或领域正确性实验。confidence、排序分、证据充分性、正式准入和实际效用是不同概念。缺资料不补固定中分，零命中仍要能显示有假设和核实路径的初步画像。

跨页 Decision 目前仅使用公开资料与公开资料形成的分析。为避免内部派生内容泄露，包含内部来源的整个分析包被省略。需要设计基于已授权 manifest 的细粒度视图，同时保留内部数据的决策价值，不能简单全开或全丢。

## 3. 新 DeepSeek 独立 Search／Fetch 应如何纳入

官方新接口：Search `POST /v1/tools/search`，Fetch `POST /v1/tools/fetch`，共用 DeepSeek bearer 鉴权。Search 可返回结构化结果并可请求 content，支持原问题与站点/日期等检索条件；Fetch 返回 Markdown。Search 的 query、ori_question 有128字符约束，count 为1–50。分别有账号级5 QPS，Fetch 另有域名限制。应在既有 ctx.web 能力接口实现 provider adapter，保留旧路径作对照与回退，而非重写全套客户端。

应比较：旧模型 web_search 回合＋普通HTTP抓取；新独立Search＋选择性Fetch；Search带content的混合方案。仅换接口不自动解决错对象、缓存占额、缺少子问题覆盖或未执行补查。Search摘要和返回content不能直接冒充经核查的完整原件；Markdown变化需要明确表示版本、原文定位及金额表格的解析方式。PDF/附件、登录和来源访问政策仍需原有合法读取路径。

中文官方价格：两种接口均5元/1000次有结果的成功请求，失败/空结果/超时不收费。编程工具内搜索的前两周优惠不能默认为工作台直接调用也适用。工具成本与模型token成本分账，依据实际成功回执核算。
