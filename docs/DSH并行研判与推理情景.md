# DSH 并行研判与推理情景

状态：依据冻结实现 `6ee45eb` 核对，更新于 2026-10-15。本轮隔离构建、部署与实际生产验收正在进行；本文说明当前源码行为，不登记生产成功或实际决策效果。

## 一次研判怎样形成建议

研判回答三个问题：要不要更新、当前值得投入什么阶段、财务和社会效果如何。宿主先沿原有资料准入和公开补查链整理本轮来源，再冻结快照。内部资料只按本轮授权进入；上一轮 AI 分析作为历史意见，原始文件和来源版本单独保留。

现有 `LiveSession` 是唯一 DSH 运行时。一次业务工作流依次包含分工、专业研究、证据上下文整理和综合研判；专业研究阶段可并行，模型调用仍通过原生 `ctx.subagents.start('spawn', ...)`，使用同一取消信号和 `maxDepth=1`。这是现有运行时上的业务流程，未引入第二套调度器或模型客户端。

| 阶段 | 输入与产物 | 执行方式 |
|---|---|---|
| planner | 来源元数据及短预览，输出 `RenewalResearchPlan`。 | 动态选择 0 至 3 个有价值的专业任务，每项分配具体问题和 1 至 10 个来源 ID；不机械凑齐三个角色。 |
| 专业研究 | 任务、来源目录及任务专属只读工具，输出 `RenewalResearchNote`。 | 工程与实施、资金与效果、居民与运营三类角色按计划并行。 |
| 上下文整理 | 已核引文、读取窗口、专家记录及失败分支。 | 保留连续原文窗口与定位，形成供综合研判使用的有限上下文。 |
| synthesis | 来源目录、原文窗口、候选原句、专家意见及原业务条件，输出 `RenewalStrategy`。 | 独立综合更新取舍、投入阶段、具体措施与财务社会效果，随后进入既有程序校验。 |

“0 至 3”是专业任务数量，不包含 planner、synthesis 及必要的原有修复调用。无须分工或目录为空时可跳过专业任务。某个分支失败后保留错误与原文，主研判继续核对可用材料；分支失败不标成已完成。

策略调用按角色保留额度：分工阶段最多 2 次；三个专业任务各最多 4 次，含读取后的继续答复与格式修复；最终综合阶段独立保留 4 次，合计最多 18 次。专家分支用尽自身额度后保留未完成记录，综合额度不被占用；其他地图研究仍沿原有 6 次限制。总时间仍受 600 秒研究时限约束。


## 只读检索与原文定位

专业角色先访问本任务的冻结来源，不能把短 ID 换成路径或目录外来源。工具复用现有分段、查询扩展、词项和主题匹配能力，支持以下参数：

| 参数 | 含义与当前限制 |
|---|---|
| `source_ids` | 本任务获准来源，1 至 10 项；宿主再校验白名单。 |
| `query` | 本地正文检索词，最多 280 字符；无匹配返回空结果。空查询可分页读原文。 |
| `offset` | 原文 UTF-16 code units 起点，默认 0；拒绝负数及拆开代理对的起点。 |
| `limit` | 返回正文字符总预算，默认 6000，最大 18000；连同元数据及 JSON 转义后的工具输出也不得超过 18000 字符。 |

每个专业任务最多调用该只读工具两次。返回片段包含 `start_char/end_char` 和来源总字符数，能用原文 `slice` 读回。工具不提供 shell、磁盘文件操作、任意网络请求或项目写入；公开补查由此前的宿主流程执行，专家不自行扩大查询范围。

事实观察中的 `quote` 必须是已返回窗口内连续、逐字相同的 8 至 280 字，`locator` 与来源登记值完全相同。程序同时检查任务 ID、来源范围、实际读取窗口和原文，不能仅凭模型声明“已阅读”通过。

## 无命中后怎样继续推理

库内检索或获准公开补查无命中时，模型仍需提出明确前提下的可执行措施。事实、逻辑推断与情景分别保存：

| 层次 | 保存方式 | 判断与用途 |
|---|---|---|
| 事实观察 | `observations`，0 至 4 项；有逐字引文和定位。 | 说明来源实际记载了什么，没有直接原文时允许为空。 |
| 逻辑推断 | `reasoned_proposals.kind=logical_inference`，列 `premises`、`conclusion`、`verification` 与可用 `evidence_refs`。 | 由明确前提提出分期、工程或服务措施；没有来源时引用可为空，不构造引文。 |
| 情景方案 | `reasoned_proposals.kind=scenario`，另列非空 `assumptions` 及适用的 `parameters`。 | 比较规模、单价、使用率、时段或补贴等假设怎样改变成本、服务与投入建议。 |

每份专家记录最多 3 项推理或情景建议。参数包含 `name/value/unit/low/high/basis`，数值有限且满足 `low≤value≤high`；范围可以来自明确的试算设定，须说明取值依据及验证方法。资料既不能形成事实观察、也没有形成任何有效推理建议时，该分支记录为未完成。

例如，没有本项目真实到餐记录时，可提出“按假定日均需求设置两档供餐规模，试运营后用去重就餐人数和餐次台账调整排班”的情景。日均需求是可调输入，不能写成已调查人数。结果变化应能回到相应输入、前提或来源；缺项清单说明怎样验证和调整方案，而不是替代具体措施。

任务记录区分 `direct_evidence`、`mixed`、`reasoned_fallback` 和 `not_produced`，分别表示直接观察、观察与推理并存、无直接观察的有效推理及未形成有效记录。推理和情景不能生成结构鉴定、资金到账、法定同意率或施工批准；原模式、工程和资金条件门继续生效。

## 上下文保留与压缩记录

宿主将原始来源正文保存在快照中，综合研判使用来源元数据、连续原文窗口、专家记录、失败任务及同批来源的候选原句。窗口优先保留专家已核引文及前后文，再保留实际读取片段与未引用来源的短预览；原文窗口正文总预算为 10000 字符。不同窗口不会拼成一条虚构引文。

trace 保存原输入字符数、来源字符数、保留窗口字符数及整理后的上下文字符数，并标记 `reduced` 或 `retained`。服务还登记综合阶段候选原句和完整来源上下文的字符数。小输入可能因元数据和专家意见而变长，因此按实际计数显示，不固定宣称节省比例；字符数不是 token 数、模型准确率或人工节省时间。

前端按服务事件显示 planning、specialists、compression、synthesis，以及每项任务的实际状态和上下文字符记录。计时不推动阶段完成，停止操作保留已收到的状态。

## AGENTS.md 与结构化工具输出

`runtime/agents/renewal/` 中的共同职责与五个角色文件由宿主固定加载。`loadRenewalAgentProfile` 只接受 planner、building_delivery、cost_value、residents_operations、synthesis，合并共同文本与对应角色文本，返回 `role/content/sha256`。未知角色在文件读取前拒绝，不接受模型传入的任意路径。

当前安装的 DSH `0.2.0-rc.1` 已提供 `SubagentStartRequest.persona`，未发现自动发现 `AGENTS.md` 的加载器。因此由宿主将固定 Markdown 注入原生 persona，并保留原基础边界和业务 Skill；不是让业务模型读取全局编程 Agent 规则或磁盘。分工、专家及综合阶段记录角色与指纹，格式和契约修复沿用同一角色内容。

结构化 tool forcing 通过已安装 DeepSeek adapter 的扩展接口设置，限本次调用作用域及非 thinking 请求：

- planner、synthesis 只有 `structured_output` 时，HTTP 请求强制选择该工具。
- 专家只有该任务只读工具与 `structured_output` 时，使用 `tool_choice=any`，允许先读片段再提交结构结果；读工具名称还须与本次允许工具完全相符。
- 其他输出类型、额外工具或 thinking 请求不套用这条强制设置。每次调用仍使用原 `outputSchema` 和工具白名单校验；普通文本即使包含 JSON，也不会被当作成功结构结果兜底解析。

模型返回后，宿主继续校验引用、参数、六维完整性、具体分项、模式条件及投入阶段。来源中的指令不能改变 persona、工具权限或这些校验。

## 六维如何呈现推理与证据

六维为居民需求、公共服务、居住工程、实施协同、长效维护、资金交付。`dimensions.current_level` 保留原文支持的现况，缺证据项继续为 `unknown`。新 `reasoning_dimensions` 另存六项逻辑或情景判断，包含等级、`basis`、前提、假设、理由、验证方式和来源；情景依据必须包含假设。

六项推理字段完整时，界面允许切换“证据画像”和“推理情景”，低/中/高显示为 1/3/5。存在 `reasoned_fallback` 且现况有未知项时可优先显示推理情景，证据画像仍单独保留。专家建议在方案尚未完成时标明部分成果；情景参数只读展示，进入现有建设资金、社区运营工作区再调整输入和测算。方案改后目标与这两类画像继续分别呈现。

页面归属与成果前 3 页、成果后 6 页的导航规则见 [界面结构与页面归属](界面结构与页面归属.md)。
