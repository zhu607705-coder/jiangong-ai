## 如何借鉴 AIHOT 的沉淀方式

参考本机 `aihot` Skill 的时间、来源与私有同步约定，复用现有 `packages/intelligence`、`vendor/aihot/algorithms` 和 `packages/corpus`。本次没有新增调度器或重复解析服务。

1. **原文优先。** 保存官方 URL、原始 HTML/PDF、获取凭证与字节哈希。省交易网页使用已观察到的 `.article-info` 容器和现有 DOM 库，避免通用 Readability 只选中长篇资格段而漏掉项目表头；PDF复用现有 Poppler。
2. **时间分开。** 原网页发布日期、平台索引更新时间、首次取得时间分别保存。HTTP修改时间及今天的收录时间不替代公告发布时间；PDF发布日期关联官方通知。
3. **版本与重复观察分开。** 复用原文 URL 的稳定身份与内容版本；同文重读和仅刷新取得时间不生成新内容版本。重复入库6份的新增数实测为0。一次条件请求返回304，复用已有快照。
4. **资料家族与事件分开。** 三个交易项目各建独立文档家族，通知和计划附件归同源家族，资金通知单独归组。初批均为开发资料；未将不同项目合并成同一事件。
5. **收录与判断分开。** 本机资料库可检索6份新资料，当前均“未分类/未精选”。本轮没有调用模型，也没有填写人为准确率、确认项目事实或自动生成历史决策理由。分类与经验复核继续走已有流程。

AIHOT 的完整私有同步有不透明游标和撤选语义。官方网页没有相同的变化流，不能把站内检索的分页参数或搜索会话号伪装成增量水位。当前只执行一次有界手动收录；若后续启用周期采集，应复用现有信源任务，并保留失败、修订及下架记录。
